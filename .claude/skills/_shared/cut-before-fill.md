# 切先于填

实现填格子；切口是设计。两刀分开。与 Karpathy「不写未来抽象 / 只改必须改」冲突时，以本文的**触发条件**为准。

结构是长期稳定的条件，不是审美。角色清楚、找文件不用猜，土也可以活；角色糊了就是泥球，下一刀只能日抛重写。禁止用「写得更优雅」当借口把实现摊进根包、打乱三档角色、或新开 `utils`/`support` 口袋。

**人在纹理，或在 loop 的缝里。** spaceXP 那种切法是把人的判断冻在目录和角色档上，不是冻在每一行。人批新切口、守三档、拒泥球、给蒸馏物点位置；模型按近邻填。人离开纹理去审文笔，或离开切口让模型自己安置，纹理就会烂，泥球就从安置权开始长。

人不得 **in loop**（当环内一步：每轮点头、当 cog），也不得 **on loop**（环外监工：看投影、看仪表、事后猜对错）。环自己在格子里跑；人只出现在**缝**——环不许自己闭合的口（新盒子、外来机制放哪、授权、完成权）。缝由人点；没点过的缝，模型不得发明。

蒸馏没错。错的是人不知道放到哪里，模型自己落档。外来机制也是切口：先点「进现盒 / 新盒 / 不进主线」，再写。

盒子一句人话、缝与纹理的表在 `memory/texture.md`。人圈之前是草案，不算切口。

约束要冻在执行层，不要冻在提示词里。上下文窗口是物理上限，不是态度问题；加厚规格或「写得更坚定」等于对墙喊话。人扎钢筋（切口、角色档、Maven 依赖、CI 机器门），模型只在格子里浇。钢筋只在「物理只读 / 测红即停」时才是钢筋——文件人人可改、只靠模型记得，仍是君子协定。模块边界先用模块墙（本仓 Maven 十组件），不要为了画红线先付分布式税。

## 切口（本仓）

未写入清单的切口，实现不得发明。`cut_list: none` 合法。

| 切口 | 谁批 |
|------|------|
| 新 `os/` 组件（新 jar） | 人（停下问） |
| 新端口 / 新 public 类型 | 人（停下问） |
| schema / 完成权 / `completed` 第二出口 | 人（停下问） |
| 外来机制安置（进现盒 / 新盒 / 不进主线） | 人（停下问） |
| 新的 loop 缝（环在此必须停、只许人闭合） | 人（停下问） |
| 本组件内抽类型、包、helper | 清单即可；第三次重复则必须抽 |
| 走已有端口复用 | 清单即可 |

## 实现前（切）

1. 打开**同一组件**里一块已满意的近邻当纹理。没有近邻 → 对着该包 `package-info` + `docs/os-baseplate.md`，不要发明第二种组织法。
2. 新文件先选角色档（端口 / `*.local` 本机实现 / persist 适配 / 测试夹具），再写。结构优先于单文件优雅；角色标本见 `.forge/project-taste.md`。
3. 写出 Cut List（或 `none`）。上表「人」行有任何一项 → 先问，再写码。
4. 派 implementer 时包里带 `cut_list`；主 session 自写时把清单写在任务计划里，再 RED。

## 第三次出现则抽

必须提取（这不是未来抽象）：

- 本组件内**第三份**同构（复制或只改名字的平行实现），或
- 行为已有端口，调用方却再写一份

抽完把该项补进清单。第一、二次重复：忍。为尚未存在的用法预留接口：禁止。

## 实现中（填）

只填清单内的格子。填的过程中撞上第三次重复 → 抽，并修订清单；若因此改了未列文件 → `DONE_WITH_CONCERNS`。

**Bug 修复默认不抽。** 除非缺陷本身就是缝没切开。

## 审核只审切口

人审与 code-review **design 维**只挑战清单：

- 清单外新增了切口？
- 第三次该抽没抽？
- 该成组件/端口却塞进现有文件？
- 新文件角色档放错（实现摊进根包、词汇层堆 `*Utils`）？
- 一次使用的 Strategy/Factory？→ 仍打 Simplicity First

**不作为 Must-fix**（Insight 或 `action: no-op`）：

- 方法级是否够优雅、可抽可不抽的 helper（第二次重复）
- 格式 / lint / 能写成测试的 import 方向——已有门用门（`PackageRoleTest`）；没有的写「应下沉机器门」，不要用人盯

bug / security / types 维不受本文收缩。

**Surgical 例外**：清单上的提取、第三次强制抽，**不是** drive-by refactor。
