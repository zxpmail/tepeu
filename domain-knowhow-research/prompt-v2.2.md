# 任务书 v2.2（技能版·唯一输入）

**技能参数**：领域词〈如 erp／crm／mes〉；可选：已有资产清单（有则注入为事实底座增量，正常情况不需要）。

---

在〈领域词〉领域，以 Agent OS（含 runtime）方式，设计领域应用基座产品，给出**网页呈现＋系列 Markdown＋可复跑的验收判据器**的交付包。方法论参照三维构造理论（语义维/数据维/动作维）。

**第〇阶段·领域 know-how 采集（先于一切设计，广度优先，带质检三件）**。**采集通道按证据类型分流**：通道 A＝web_search/web_fetch；通道 B＝有头真 Chrome（headed＋本机 Chrome＋`--disable-blink-features=AutomationControlled`，headless 会被软封锁）；通道 C＝人工投喂；**通道 D＝仓库克隆＋代码托管平台 API（软件格局面主力：trees API 拿文件树＋raw 读源码，证据记源码路径；生态统计走 search API）**。通道策略：A∥B 同组并行、软件面走 D。三通道产物同构入**原始层** `research-raw/`（按来源分件：URL＋取证日期＋通道号＋摘录，不消化不改写）；**规模条款**：采集量 ∝ 查询组数 × 轮次，查询组按「面」设计，缺面即盲区。全不可用时走记忆降级态。围绕领域词采集——行业标准与国标、业务流程与单据生命周期、角色职责与日常任务、术语与行话、常见痛点与失败案例、主流软件与开源项目（商业＋开源分账）。消化层为**领域 know-how 册**（四分册：术语与本体／业务流程与单据／角色与痛点／软件与工具格局），每条带 URL＋取证日期＋证据分级＋回指 raw 件号。质检三件：
①**交叉验证**——关键结论（数字、排名、因果断言）至少 2 个**相互独立**的来源才标「已证」，警惕伪多源（同一叙事被多处转引只算一源）；单来源标「单源待证」，零来源的凭记忆内容标「推断·记忆源」；
②**饱和判据**——连续一轮补充检索（新增 20 条）无新增类别、无新增分册条目，即判采集饱和收口，并在册头登记「检索轮次与饱和依据」；
③**版本回流门**——know-how 册带版本号，运行期经验回流可修订（修订走变更记录，旧结论不删除改标注「已被 vX.Y 修订」），册子是「当前最佳认知」不是终局真相。
**证据分级与升级通道**：已证（多独立源带 URL）／单源待证（带 URL 单源）／推断·记忆源（无 URL，记忆多源与单源同级）／未证。升级通道：记忆态条目检索可用后逐条在线核证——核到带 URL 的独立来源即升级、核不实即降级或删除；升级走版本变更记录，不覆盖原条目。四级分账禁止互冒。**消化层落盘即事实底座**，后续一切阶段的取材只引册号；原始层归同类调研任务直接消费。

**产品定义**（既定，不另行发明）：
1. **产品构造**＝领域工具链集成（MCP）＋领域认知本体构建（认知基座）＋领域典型应用架构（配备 agent），以 Agent OS（含 runtime）方式，通过 agent 灵活组装实现各类功能，同时保留原始页面功能按钮操作流程；
2. **主界面**＝对话框＋相关 I/O 功能；对话是完备的；结构化卡片按类型分类（数据呈现、选择决策、情报汇报等）；
3. **输入约束**：对话/文件执行任务时具备输入约束能力，输入不足或非法时拒绝、选择、补充或提示；
4. **智能能力**：数据分析、报告生成、评估分析、动态呈现等 agent 能力；
5. **呈现封装**：特定前端＋参数注入形式，由 agent 调用灵活组装呈现。

**要求**：需求覆盖领域核心场景（按 know-how 册实际格局划定，真问题真需求），要有证据链——全部回指 know-how 册号，外部论断一律在线检索取证带 URL，检索不可用时该维度整层标「未证」申报，禁止凭记忆冒充已证；调研同类产品 ≥10 场景；角色按 know-how 册角色面展开；认知上重点回答两个深水区——语义维中怎么做规则（如何表示/从哪来/怎么校验/怎么演进）、特殊问题怎么处理（例外/异常/歧义/冲突/边界的处置规则），每条规则带可测试断言。

**启动三步（know-how 册落盘后，先于一切分解）**：①列出全部交付物类型与数量，每件标注消费方、装载点、验收口径——此清单是唯一停止条件，「颗粒度到可直接开发、具体到单个模块」即判停线：一个工程师拿它就能开工才准停；②建立任务执行序列、决策日志、审计记录三本管控账，此后任何范围变更先记账后执行；③各层递归展开：每层先立提纲、对齐冻结，再照模板批量填充——冻结前不得开下层，填充层零判断零自创，发现问题折回提纲层记次数，禁止在填充层打补丁。

**纪律**：概念与规则引用不重写（新增标[新增]带依据）；关键论断带出处（know-how 册号或 URL），判定四级分账，未证集中申报；完备性不用对数清单，用多独立维度穷举（标准/角色旅程/单据生命周期/事件驱动/数据消费），候选缺口三证据裁决；启动独立子 agent 多维度评审优化，多轮评审修改，问题闭环到「无未完成项」。

**执行**：goal 模式，长程执行，工程化项目制管理，充分比较各类方案，深度考虑，逻辑严谨，成果科学可靠、设计可机判、运行可实证、可执行可落地。
