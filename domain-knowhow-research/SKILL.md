# 领域 Know-how 采集与研究

## Overview

输入一个**领域词**，第〇阶段自采领域 know-how（四通道采集 → 两层 raw → 质检三件 → 四级分级 → 合并互证），产出《know-how 册》作为事实底座；此后可选按 [prompt-v2.2.md](prompt-v2.2.md) 生成整套文档体系。

**核心原则**：know-how 是搜出来、汇出来的**产物**，不是预先喂进来的输入；无证据不冒充（无 URL 一律不得标已证）。

## 采集通道（选择按证据类型分流，勿单通道裸跑）

| 通道 | 工具 | 适用 | 实测要点 |
|---|---|---|---|
| A | web_search/web_fetch（账号或 key） | 官方文档站、商业产品 | 锋利但抓取成功率≈32%（403 拦截多），单靠它会漏面 |
| B | **有头真 Chrome**（Playwright＋本机 Chrome＋`--disable-blink-features=AutomationControlled`） | 搜索引擎广度采集 | headless 裸跑会被软封锁——**必须 headed＋真 Chrome＋去自动化标志**（实测封锁在自动化特征不在 IP） |
| C | 人工投喂 | 用户给 URL/文档 | 全网不可用时兜底 |
| D | GitHub trees API＋raw.githubusercontent | 开源软件格局（**主力**） | `git clone` 可能被网络重置→用 `api.github.com/repos/<o>/<r>/git/trees/master?recursive=1` 拿全量文件树＋raw 读源码，证据记**源码路径**（密度上限最高，零反爬）；生态统计走 search API（无 key） |

**通道策略**：A∥B 同组查询并行（两面互补、重叠面互证），软件格局面走 D；合并消化时**跨通道互证可升已证**（同站互抄＝伪多源，算同源，不得升）。

## 两层结构与质检三件

```
项目目录/
├─ research-raw*/          ← 原始层：按来源分件，URL＋取证日期＋通道号＋摘录，不消化不改写
└─ know-how册-<领域>.md     ← 消化层：四分册（术语本体/流程单据/角色任务/痛点＋软件格局）
                             条目格式：编号｜条目｜raw 件号｜URL｜证据分级｜备注
```

质检三件：①**交叉验证**——关键结论 ≥2 相互独立来源才标已证；②**饱和判据**——一轮补充检索无新增类别即收口（饱和依据入册头）；③**版本回流门**——册带版本号，运行经验可修订，旧结论标注不删除。

## 证据四级与升级通道

已证（多独立源带 URL）＞单源待证（1 个 URL）＞推断·记忆源（无 URL，记忆多源与单源同级——记忆一致性只代表内部自洽）＞未覆盖。检索可用后逐条在线核证：核到独立来源即升级、核不实即降删，走版本变更记录。**记忆内容永远不能直接标已证**。

## 采集器

[collectors/](collectors/) 内：collector-v8.js（通道 B 定版，node＋playwright，queries.txt 放查询组）、collector-v5.ps1（无浏览器环境降级版）。查询组**按面设计**（每个知识面一组查询）——单轮单通道的产出只是试点量级，采集量 ∝ 查询组数 × 轮次。

## 全文档体系生成（可选）

know-how 册落盘后，用 [prompt-v2.2.md](prompt-v2.2.md) 作唯一任务书输入（产品定义五条/第〇阶段/启动三步/判叶器/纪律）。执行体第一轮**自生成细则**（场景归并判据、卡模板、审计维度），提示词不替执行体写细则。

## Common Mistakes（全部有实测教训）

- 用记忆填腔冒充已证 → 实测记忆版 53 条 0 已证；记忆只能推断级
- headless 裸跑搜索引擎 → 软封锁返回垃圾结果；headed 真 Chrome 实测全通
- 单通道当全部 → A-only 把失败案例面打成零材料；6 面盲区全是查询组设计缺口
- 大站 403 拒命令行 → 浏览器指纹或 r.jina.ai 兜底
- 克隆 2GB 大仓库 → trees API 等效且更轻
