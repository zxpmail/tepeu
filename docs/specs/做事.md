总规则：[`../rewrite-1.md`](../rewrite-1.md) 第 2.3、7 节。放行次序见 [检查口.md](./检查口.md)。

本文写 `work` 里的这些类：问模型、读东西、写东西、Grep、Glob、Edit、跑命令。检查口前置过了才叫它们。它们不写步骤记录，不写做完，不决定放不放行。下面表里的做完、没做完由判断写入，过程记录由一轮写入。这里看的是整轮结果。

问模型读本机 cc-switch 里当前的 Claude 供应商，这一家是 Xiaomi MiMo。地址和模型从那里读，密钥留在本机，不进程序，也不进步骤记录。别的密钥怎么认，还没定。读出的字会进步骤记录。密码和密钥不给人看。

## 问模型

发出去的是给模型看已经准备好的那几行，不另编，也不改。交回成功时正文里必须有字。没有字，检查口改记失败。不用点头，也不看范围。问模型自己不放行读、写、跑。正题认不认点名，见 [一轮.md](./一轮.md)。

问模型成功不能单独算做完。

```mermaid
sequenceDiagram
  participant gate as 检查口
  participant ask as 问模型
  gate->>ask: 把已经准备好的几行原样发出去
  ask-->>gate: 成功并且有字，或失败，或成功但没有字
  Note over gate: 没有字就改记失败。平台返回由检查口写
  Note over ask: 不写步骤记录，不说做完
```

| 编号 | 输入 | 必须看到 |
|------|------|----------|
| Q-02 | 问模型和费用都交了，费用这一次够，三个字段合格，交回成功并且正文有字，正文不是整行点名 | 平台返回抄了这次任务的编号，写入者是 `gate`，种类是成功。有一笔「没做完」。没有「做完」 |
| Q-03 | 同 Q-02，但正文是「做完了」 | 平台返回在，种类是成功。有一笔「没做完」。没有「做完」 |
| Q-04 | 同 Q-02，但没有文字 | 平台返回的种类是失败，不是成功。有一笔「没做完」。没有「做完」 |

## 读、写、跑

范围过了才到这里。读不问点头。写和跑还要人已经点头。

读是把文件里的字交回来。目标是目录时，交回里面每一项的名字，一行一个。写是把点名行下面的那些字写进那个文件，不写人交的「要做什么」。跑是启动那个程序，参数是点名行下面的非空行，每行一个，不经过系统外壳，也不拼成一条命令。不启动 cmd、powershell、bash、sh。限制是目录就在那个目录里跑；限制是文件就在它所在的目录里跑。等它自己结束。退出码是 0 才算成功。一直不结束，最多等 5 秒，记结果种类「超时」，然后不再等。

模型交来的 `Read` 就是读，`Write` 就是写。`Grep` 用正则在限制里找，最多交回 100 行，超过 1MB 的文件不搜，多了就写「还有更多」。`Glob` 按名字找文件，最多 200 个。`Edit` 把文件里唯一的一段旧字换成新字；没有，或不止一处，就不改。这三样都不经过命令外壳。`Grep`、`Glob` 不问点头。`Edit` 要人点头。

判断时不再打开文件核对。写交回成功，就按成功看。

读、写、跑各是一次放行。不会在同一次放行里连着做这三件。正题要碰到这三样，问模型的成功正文里要先有对应的整行点名。下面四条都是已经点名、检查口已经放行之后的整轮结果。下一次问模型的正文没有点名。

读。范围过了才到这里。不问点头。

```mermaid
sequenceDiagram
  participant gate as 检查口
  participant read as 读东西
  gate->>read: 范围已过。这一次只读
  read-->>gate: 文件里的字
```

写。范围过了，并且人已经点头，才单独放行这一次。

```mermaid
sequenceDiagram
  participant gate as 检查口
  participant write as 写东西
  gate->>write: 范围过了，人已同意。这一次只写
  write-->>gate: 写入结果
```

跑。和写一样，单独放行。退出码不是 0 不算成功。超过 5 秒记超时。

```mermaid
sequenceDiagram
  participant gate as 检查口
  participant run as 跑命令
  gate->>run: 范围过了，人已同意。这一次只跑
  run-->>gate: 退出码。不是 0 不算成功。超过 5 秒记超时
```
