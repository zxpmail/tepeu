# 接口设计

正式路径前缀 `/api/daf/v1`。错误体见总体设计第 8 节。除健康检查外都要令牌。

写操作幂等：请求头 `Idempotency-Key`。作用域是租户、调用者、路径、该键，窗口见字面量 `LIT-C-IDEMPOTENCY-HOURS`。只有状态已经成功的请求才回放第一次的结果。已回滚或未见提交的，同一键必须允许再执行。进行中的重复请求返回 409，文案 `RC-PACKAGE-CONFLICT`，不并行开第二次。

## 1. 应用

| 方法与路径 | 权限点 | 成功 | 失败 |
|---|---|---|---|
| POST /apps | 令牌 roles 含平台角色 | 201 应用 | 409 `RC-PACKAGE-CONFLICT` 键重复 |
| GET /apps/{appKey} | 应用成员或管理员 | 200 应用 | 404 `RC-APP-NOT-FOUND` |
| POST /apps/{appKey}/publish | 应用管理员 | 200 | 409 `RC-APP-STATE` |
| POST /apps/{appKey}/suspend | 应用管理员 | 200 | 409 `RC-APP-STATE` |
| GET /apps/{appKey}/routes | 成员 | 200 路由列表 | 已停用且不是应用管理员时 403 `RC-PERM-DENIED` |
| PUT /apps/{appKey}/routes/{routeId} | 应用管理员 | 200 | 422 `RC-SCHEMA-INVALID` |

应用响应字段：`appKey`、`name`、`state`、`version`、`tenantId`、`projectId`。查询只按令牌租户和项目过滤，不先按应用键全库查找。查不到即 404，文案 `RC-APP-NOT-FOUND`。若路径、查询参数或 JSON 正文另带 `tenantId` 且与令牌不一致，403，文案 `RC-TENANT-MISMATCH`，`details` 为空对象。`RC-APP-STATE` 只用于 409。已停用应用上，非应用管理员访问路由用 403，文案 `RC-PERM-DENIED`。

## 2. 成员与角色

| 方法与路径 | 权限点 | 说明 |
|---|---|---|
| PUT /apps/{appKey}/members/{uid} | 应用管理员 | 体：`roleKeys` 数组。空数组表示移除成员 |
| GET /apps/{appKey}/roles | 应用管理员 | 角色及权限点 |
| PUT /apps/{appKey}/roles/{roleKey} | 应用管理员 | 替换该角色的权限点集合 |

权限点字符串匹配 `^[a-z][a-z0-9]*(\.[a-z][a-z0-9]*){2}$`，三段：应用键、实体键、动作。动作只允许 `read` `create` `update` `delete`。

## 3. 页面与外壳

| 方法与路径 | 说明 |
|---|---|
| GET /apps/{appKey}/shell | 外壳读模型：应用名、状态、菜单（由已发布路由生成）、当前用户权限点 |
| GET /apps/{appKey}/pages/{pageKey} | 页面模式。校验不在读路径做第二次；读到的必须是已校验版本 |
| PUT /apps/{appKey}/pages/{pageKey} | 仅草稿应用。已发布应用一律 409 `RC-APPROVAL-REQUIRED`，即使带着组装号。已发布变更只走组装落地 |

## 4. 数据

| 方法与路径 | 说明 |
|---|---|
| POST /sources | 登记数据源。体：`type`、`credentialRef`、`endpointRef`。无密钥字段 |
| POST /sources/{sourceKey}/probe | 探测。结果写入最近状态 |
| POST /apps/{appKey}/entities | 定义实体 |
| POST /apps/{appKey}/entities/{entityKey}/query | 体：`filter`、`sort`、`pageSize`、`page`。`pageSize` 上限 100 |
| POST /apps/{appKey}/entities/{entityKey}/commands | 体：`action`、`payload`。动作来自语义包 |

查询响应：`rows`、`total`（源能计数才返回，否则 `total` 为 null 且 `totalKnown` 为 false）。

## 5. 组装与安装

| 方法与路径 | 说明 |
|---|---|
| POST /apps/{appKey}/assemblies | 创建提议 |
| POST /assemblies/{id}/validate | 校验 |
| POST /assemblies/{id}/apply | 落地。已发布应用缺审批号则 409 |
| POST /assemblies/{id}/rollback | 补偿。只有 APPLIED 可回滚 |
| POST /packages/install | 体为清单。无外接源时必须在 `LIT-C-INSTALL-SEC` 内以 200 结束，状态为成功或已回滚，禁止 202。有外接源时，事务外探测若满 `LIT-C-INSTALL-ASYNC-SEC` 仍未结束，返回 202 和安装号；此时只许先有一行进行中，不得写业务表 |
| GET /packages/installs/{installId} | `RUNNING` `SUCCEEDED` `ROLLED_BACK` |

轮询间隔不得小于 `LIT-C-POLL-MIN-MS`。探测失败把进行中改为已回滚，不开启安装事务。

## 6. 桥接（基座调用 gnex，不是给浏览器的）

这些调用只允许 `daf-brg` 发起。

| 调用 | 用途 | 缺失时 |
|---|---|---|
| 校验令牌 | 得到 tid、uid、projectId | 拒绝全部业务请求 |
| 读组织成员（只读） | 可选，用于挑选人 | 应用成员仍可手工按 uid 添加 |
| 提交审批 | 已发布组装进入待审批时提交摘要，得到审批号 | 提交失败则保持已校验，不进入待审批 |
| 核对审批 | 落地前再核对一次，不缓存 | 未通过则不落地 |
| 投递审计 | 写后 | 写入 outbox |
| 解析凭证引用 | 连接器取连接信息 | 该数据源探测失败，已打开的页面读操作失败码 `RC-SOURCE-DOWN` |

gnex 侧的具体 URL 不写死在规格正文。部署配置键：`gnex.auth-introspect-url`、`gnex.approval-url`、`gnex.audit-url`、`gnex.credential-resolve-url`。路径形态若与 gnex 企业规格不一致，改配置，不改基座模块。

## 7. 事件

基座发到 gnex 总线的事件名：

| 事件 | 时机 |
|---|---|
| daf.app.published | 应用变为已发布 |
| daf.app.suspended | 停用 |
| daf.package.installed | 安装成功 |
| daf.package.rolled-back | 安装回滚 |
| daf.assembly.rolled-back | 组装回滚。不复用安装回滚事件 |
| daf.assembly.applied | 组装落地 |
| daf.audit.dispatch-failed | 审计外发失败（同时进本地队列） |

载荷公共字段：`tenantId`、`appKey`、`actorUid`、`occurredAt`、`traceId`。禁止载荷携带行数据全文和密钥。
