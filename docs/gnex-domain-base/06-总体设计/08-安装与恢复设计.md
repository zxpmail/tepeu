# 安装与恢复设计

## 1. 清单

清单是 JSON，媒体类型 `application/vnd.gnex.daf.package+json`。

必填：`packageKey`、`version`、`appKey`、`appName`、`depends`、`entities`、`pages`、`migrations`。

可选且仅此：`services`、`semantic`、`hooks`、`publish`、`upgradePath`。其余字段拒绝。

`publish` 缺省 false。`upgradePath` 是字符串数组。`depends` 是对象数组，每项含 `packageKey` 与 `version`，已装版本的三段数字必须大于等于该项。

`hooks` 每项只含 `serviceKey`。该键必须是已登记或本次清单同时登记的 `biz.` 服务。不含类名、源码、脚本。首版不加载 jar。

## 2. 安装顺序

1. 校验清单字段。未知字段拒绝。
2. 校验依赖已安装且版本满足。
3. 外接源在事务外探测。失败则写入或更新安装记录为已回滚，不开始业务事务。无外接源则没有这一步。
4. 锁住租户内该 `appKey`。同一版本、另一把幂等键：返回 409，不再建表。同一幂等键且已经成功：回放第一次结果。同一幂等键但是已回滚：允许再执行。
5. 开始数据库事务：写入应用，状态为草稿。`publish` 为 true 时，同一事务写入调用者的成员行，角色为 `app-admin`。
6. 托管实体执行迁移里的建表。外接实体只写映射，事务内不再探测、不再访问网络。
7. 写入页面模式与路由。路由先处于未发布。
8. 写入语义包版本。登记 HTTP 钩子的服务键。缺少该服务则回滚。
9. 写安装记录为成功。若 `publish` 为 true，再发布。发布失败则整单回滚。

有外接源且探测满 `LIT-C-INSTALL-ASYNC-SEC` 仍未结束：先提交一行进行中并返回 202。探测失败则把该行改为已回滚。无外接源的标准包禁止 202。

## 3. 不能放进该事务的事

探测和任何对 gnex 的调用都在事务外。事务内不发网络。审批不出现在安装路径。安装不是智能体工具。`publish=true` 表示平台管理员确认首发，不表示智能体可以免审批改已发布应用。

## 4. 升级

- 版本必须严格高于已装版本。主版本变化一律拒绝，文案 `RC-PACKAGE-CONFLICT`。
- 相邻的定义：主版本相同；次版本差最多 1；次版本相同时修订差为 1；次版本加 1 时修订号必须为 0。
- 不是相邻升级时，`upgradePath` 必须从已装版本起逐级连续，每一级都有 `fromVersion` 等于上一级的迁移。否则拒绝。
- 升级事务只做前进迁移。失败则版本保持不变。
- 删字段不在升级事务里物理删除。迁移把字段标为退役，查询默认不返回。物理删除首版不做。

## 5. 恢复

| 故障 | 行为 |
|---|---|
| 进程在事务中被杀死 | 数据库回滚未提交事务。若幂等记录不是成功，同一键可以重试 |
| 审计投递失败 | 业务事务只插入外发队列，事务内不访问 gnex。工作器负责投递。超过 `LIT-C-OUTBOX-HOURS` 仍失败则另插一行不再投递的失败事件，此前失败只增加次数 |
| 组装已落地后要撤销 | 用事务前像写回页面与实体差异。物理表上已新增的可空列保留，标记退役，避免丢已写入的值 |
| 令牌服务不可用 | 新请求拒绝。不使用上次成功的令牌缓存 |

## 6. 标准包计时

标准包定义：1 个托管实体（不超过 15 个字段）、1 个列表页、1 个表单页、无钩子、无外接源、`publish=true`。

从 `POST /packages/install` 接受到路由对调用者（安装时写入的 `app-admin` 成员）可解析，墙钟不超过 `LIT-C-INSTALL-SEC`。标准包无外接源，响应是 200 而不是 202。发布者是平台管理员，不走智能体审批。
