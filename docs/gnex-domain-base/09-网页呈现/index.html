gnex 领域应用基座

智能体操作系统负责把事情规划并跑起来。基座负责让不同业务系统用同一套方式装上去：人与权限、应用与菜单、业务服务、标准页面、多来源数据、可审批的智能组装。

分界 七块能力 一套系统怎么来 规格 完整说明

和 gnex 的分界

业务系统　请假、巡检、资产等应用包。规则放在自己的钩子里。
领域应用基座　应用、路由、页面模式、实体、查询、语义包、安装事务。独立进程。托管数据同时按租户和项目隔开。
gnex3　租户硬边界、登录、组织、审批、审计、凭证、智能体循环、模型、沙箱、记忆。基座只调用，不重做。

基座停了，正在 gnex 里跑、且不再访问基座的那一轮智能体仍应跑完。基座不把业务查询塞进智能体进程。

七块能力

身份核验 gnex 令牌。应用内成员和数据权限另记。不自建用户库。
应用草稿、发布、停用、退役。菜单由已发布路由生成。
服务登记业务接口和健康。键以 biz. 开头，避免和 gnex 内部服务重名。
界面六种标准区块。页面格式不绑死某一组件库。
数据托管表或外接 PostgreSQL、MySQL、REST。查询强制带租户。不提供任意 SQL。
智能组装智能体提交结构化差异。已发布应用必须先过 gnex 审批。
应用包清单安装。失败则回到安装前。标准包 60 秒内可打开。

一套系统怎么来

  1. 管理员登记数据源，或使用基座托管库。
  2. 安装应用包。包里有实体、页面、语义和可选的业务钩子。
  3. 把人放进应用并授予角色。
  4. 业务用户从外壳进入菜单，列表和表单经统一查询读写。
  5. 要改已发布页面时，智能体提议，审批通过后才落地。

取舍（摘要）

决定不这样做的原因
独立服务，而不是塞进智能体进程业务安装和页面流量不应重启智能体循环
登录沿用 gnex两套账号会停用不同步
元数据用 PostgreSQL与现有租户行级隔离同一套路。不把应用定义放进另一套文档库
首版不做大查询引擎第一批系统是单据，不是分析仓。跨源超过一万行估算就拒绝
页面不使用某一低代码产品的私有 JSON换界面实现时不应重写全部历史页面

规格入口

开发按单模块规格开工。数值和错误文案以字面量库为准。

规格做什么
登录上下文核验令牌，失败即拒绝
应用授权成员、角色、行过滤、打码
应用注册应用状态
路由路径与菜单
服务目录业务服务与健康
页面模式正式页面格式
外壳中文标准界面
数据源三种连接，密钥只留引用
实体托管建表或外接映射
查询与命令下推、拒绝任意 SQL、跨源上限
语义包给人和智能体读的说明
组装事务提议、审批、回滚
安装升级事务、回滚、禁跳版
