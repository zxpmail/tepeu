# 同类产品调研

取证日期 2026-11-03。分级：已证 = 下表 URL 能对上该行结论；单源 = 只有一处公开材料。记忆不升已证。

匹配度 1–5：5 表示机制可直接搬进「gnex 旁边的业务应用基座」。

## 1. 对照表

| 产品 | 它解决什么 | 优势（相对本任务） | 劣势（相对本任务） | 匹配 | 证据 |
|---|---|---|---|---|---|
| NocoBase | 插件里定义集合，界面用区块拼数据 | 集合、区块、数据源是分开的扩展点，和「组件拼装」同构 | 身份和租户自建；没有智能体组装事务；插件集合默认不出现在数据源管理里 | 4 | 已证 https://docs.nocobase.com/plugin-development/server/collections |
| Frappe | 单据类型即模型+界面，应用装到站点上 | 元数据驱动、应用安装、站点之间数据库隔离，适合「业务系统是包」 | Python 运行时；同一站点内应用共享一库，和 gnex「行级租户硬过滤」不是同一隔离粒度；Desk 过重 | 4 | 已证 https://docs.frappe.io/framework/user/en/basics/doctypes 与 https://docs.frappe.io/framework/user/en/basics/sites |
| Directus | 在已有库上加集合元数据、字段界面、条目权限 | 系统表与业务表分开；外接库可被映射；权限可按条目过滤 | 多租户是用法（自建租户集合+过滤），不是产品内核；没有应用包事务 | 4 | 已证 https://directus.com/docs/guides/data-model/collections |
| Appsmith | 工作区里的应用、数据源、组件、查询 | 数据源在工作区内复用；组件用查询绑定，适合内部工具 | 应用定义在 Mongo；社区版按工作区分享，不是应用级；查询脚本容易漏掉租户条件；行级安全曾是未关闭需求 | 3 | 已证 https://docs.appsmith.com/build-apps/overview 与 https://github.com/appsmithorg/appsmith/issues/13941 |
| ToolJet | 数据源插件 + 查询 + 组件；插件用清单描述连接表单 | 连接清单把密钥标成加密字段，和「密钥只留引用」同方向 | 仍是应用构建器，页面可带表达式；不是领域包，也没有企业租户硬边界 | 3 | 已证 https://docs.tooljet.com/docs/contributing-guide/marketplace/creating-a-plugin/ |
| Odoo | 模块清单声明依赖、数据文件和安装钩子 | 「业务系统 = 模块」这一包装方式成熟；升级走模块版本 | 多公司不是硬租户；视图 XML 与基座页面模式不是同一语言；运行时是 Odoo 单体 | 3 | 已证 https://www.odoo.com/documentation/20.0/developer/reference/backend/module.html |
| Hasura | 用元数据描述源、关系、权限，查询下推到连接器 | 「能下推就下推、连接器暴露源的原生能力」适合统一查询 | 它是数据访问层，不是应用壳，也不做组装审批。分布式版商业属性重，首版不嵌入 | 3 | 已证 https://hasura.io/blog/consolidated-data-access-in-hasura-ddn-with-data-connectors |
| Backstage | 软件目录 + 彼此只走网络的插件 | 服务要登记、要健康、插件故障域分开。可借鉴目录字段 | 官方扩展路径是每组织一套实例，不是行级多租户；对象是研发资产不是业务单据 | 2 | 已证 https://github.com/backstage/backstage/blob/master/docs/backend-system/architecture/04-plugins.md |
| Cube Core | 在数仓之上定义指标、维度、权限，供人和智能体查询 | 说明「语义要有唯一出处，否则智能体每次自己发明口径」 | 对象是分析指标，不是业务单据的增删改。首版实体 CRUD 用不上整套预聚合 | 2 | 已证 https://cube.dev/use-cases/semantic-layer |
| Amis | 用 JSON 描述页面并渲染 | 证明 JSON 页面能覆盖大量中后台区块 | 模式是 Amis 专有的。把它当正式格式，以后换渲染器要重写全部页面 | 2 | 已证 https://github.com/baidu/amis/blob/master/examples/components/SchemaRender.jsx |
| Budibase | 内置数据、自动化和界面的低代码 | 上手快，适合单库内部工具 | 多源异构和企业硬隔离不是它的中心；与智能体运行时无边界契约 | 2 | 单源 https://budibase.com/ |
| Corteza | 开源低代码模块 | 有模块化低代码先例 | 公开材料不足以证明企业级租户硬隔离和组装审计，不作为结构样板 | 1 | 单源 https://cortezaproject.org/ |

商业产品只作问题清单，不作结构样板：明道云、简道云一类国内零代码平台能拼表和页面，但是封闭运行时，不能插入 gnex 的租户与审批。此句为推断，不作为选型证据。

## 2. 取什么、不取什么

| 机制 | 采纳 | 不采纳及反例 | 复决条件 |
|---|---|---|---|
| 元数据描述实体 | 采纳。实体是数据，页面指向实体 | 不把实体写死在 Java 类里。反例：每加一种单据就要发一版基座 | 若某类单据 80% 的字段无法用字段类型表表达，重开类型系统 |
| 应用是可安装的包 | 采纳。清单 + 迁移 + 依赖 | 不采用「一个 Git 仓库里手写前后端就算一个应用」作为唯一路径。那种做法无法让智能体组装 | 若钩子需求超过清单的 50%（按第一批两个业务系统统计），重开代码应用模板 |
| 页面模式与渲染器分离 | 采纳 | 不把 Amis 或 ToolJet 的组件 JSON 当正式格式。反例：渲染器一换，历史应用全失效 | 若官方渲染器对第一批两个业务系统的标准页面覆盖低于 80%，允许 Amis 作默认渲染器，正式格式仍保持不变 |
| 查询下推 | 采纳单源下推 | 不在首版内嵌 Trino。反例：为了偶尔跨库分析，运维要多养一个查询集群，业务安装被拖慢 | 若连续一个月有 ≥10 次合法业务页面因跨源上限被拒，重开分析型查询引擎 |
| 工作区当租户 | 不采纳 | Appsmith 工作区会把数据源暴露给工作区内全部开发者。gnex 要求的是令牌租户硬过滤，粒度更细 | 无。与 D-002 冲突，不复决为工作区模型 |
| 第二套身份 | 不采纳 | Casdoor、Directus 用户表都会和 gnex `auth` 抢登录。反例：同一人两套口令，停用不同步 | 仅当 gnex 认证无法提供租户、用户、项目三个声明时重开。该前提由桥接规格的探测验收守住 |
| 指标语义层 | 首版不纳入 | Cube 解决「收入怎么算」。基座首版解决「这张单能不能存」。混在一起会使实体命令和指标预聚合绑死 | 出现第二个消费同一指标的业务系统时再单独立项 |
| 插件热加载业务系统 | 首版不采纳 | gnex 自己的热装都排到 v3.1。基座安装用事务和重启窗口，不用类热替换。反例：热替换失败留下半个类 | gnex v3.1 热装稳定且基座安装 p95 仍 > 60 秒时再评估 |

## 3. 和 gnex3 的空档（调研结论）

上表产品要么强在界面和数据（NocoBase、Frappe、Directus、Appsmith），要么强在目录（Backstage），要么强在查询（Hasura、Cube）。没有一个同时满足：

1. 身份以现有企业智能体操作系统的租户令牌为准；
2. 业务系统以包的形式安装和回滚；
3. 页面模式不绑死某一渲染器；
4. 智能体改配置必须走可审批的事务，而不是改脚本或直写库。

基座补的是这四条的交集，不重做上表里已有的整套低代码产品。
