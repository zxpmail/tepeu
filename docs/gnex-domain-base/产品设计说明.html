产品设计说明

gnex 已经能调度和运行企业里的智能体。它还不是请假系统、巡检系统或资产系统。这些系统如果各自从头做用户、菜单、单据和接口，就无法形成集群，智能体也无法用同一套办法去配置它们。

领域应用基座是这层空白。业务系统在上面组合，而不是在基座里写死某一个行业。

五条产品定义

  1. 身份以 gnex 令牌为准。基座只增加「这个人在这个应用里能看哪些行」。
  2. 一个业务系统是一份可安装、可回滚的应用包。
  3. 页面用基座自己的模式描述。换界面实现不必重做历史页面。
  4. 数据可以在基座建表，也可以映射到已有的库和 REST。任何查询都带租户条件。
  5. 智能体只能提交组装单。改已经发布的应用，必须经过 gnex 的审批。

首版做到哪

人能装上一个含列表和表单的标准包，在 60 秒内打开。能授权、能停用、能在安装失败时回到原点。智能体能给草稿应用加页面；给已发布应用加页面时没有审批号就会被拒绝。跨源数据量过大时拒绝，而不是拖死连接。

首版不做：第二套登录、任意 SQL、分析指标平台、行业成品、手机专用壳、页面里的脚本。

实现落点

一个 Java 21 服务，旁边一个 React 外壳。模块按身份、应用、服务、界面、数据、语义、安装、桥接分开。错误文案和上限数字集中在规格字面量库，避免前后端各写一句。
