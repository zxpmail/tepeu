# 决策日志

日期一律 2026-11-03。依据分两档：`已证` 回指文件或 URL；`设计` 是本轮拍板，复决条件写在条内。

| 编号 | 裁决 | 依据 | 影响件 |
|---|---|---|---|
| D-001 | 领域应用基座是 gnex 旁边的独立服务，不放进 agent 循环进程，也不做成 cordis 内核插件 | 设计，不是 gnex 已有结论。融合设计原文是九个服务保留，插件在服务内组合。基座是第 10 个部署，属于例外：业务安装和页面流量不应重启智能体循环。复决：若企业层要求业务元数据只能经受保护插件访问，则取消独立进程，改回 gnex 内的受保护插件 | 06-总体设计、spec-brg |
| D-002 | 身份、租户硬边界、组织、认证签发仍以 gnex3 企业层为准。基座只保存「人在某个应用里的成员、应用角色、数据权限」 | `v3-spec-ent-tenant` 写明非目标含认证签发与业务级授权；`v3-spec-ent-auth` / `ent-org` 是受保护插件 | spec-idn-* |
| D-003 | 元数据放 PostgreSQL 16，表带 `tenant_id` 和 `project_id`。行级安全是基座自己的设计，不把 gnex 租户规格里尚未核实的类名当作已落地 | 设计。gnex 租户规格写明相关拦截器类名在核实前不得当验收基线。Appsmith 用 Mongo，不沿用。复决：基座库若无法强制非属主角色走策略，隔离验收判失败，不得改成只靠应用里的 WHERE | spec-dat-entity、spec-idn-context |
| D-004 | 页面的正式格式是基座自己的页面模式。Amis 只能做可选渲染器，不能当正式格式 | Amis 的 `render(schema)` 吃的是它自己的 JSON。换渲染器会被迫重写全部页面 | spec-ui-schema |
| D-005 | 首版统一查询只做单源下推，加上有行数上限的跨源拼接。不内嵌 Trino / Calcite 集群 | 首批业务系统是表单和列表，不是分析仓。引入查询集群会把基座变成第二个数据平台 | spec-dat-query |
| D-006 | 语义包用受控词表的 JSON 文档，不用 OWL 推理库 | 组装要让智能体填表、让人审得懂。类型继承推理不是首版失败点 | spec-sem-package |
| D-007 | 智能体改应用只能走组装事务。已发布应用的组装落地必须核对 gnex 审批。平台管理员的首次安装不是智能体工具，不走这道审批，但必须审计 | 设计。审批规格禁止的是插件或智能体绕过。安装接口不在五个工具里，智能体调不到。复决：一旦安装被做成工具，本例外取消，安装也必须带审批号 | spec-sem-assemble、spec-pkg-install |
| D-008 | 能力切成七块：身份、应用、服务、界面、数据、语义组装、应用包。行业包不做 | 用户要的是统一抽象基座，不是某一行业系统 | 07-分域、11/12 豁免 |
| D-009 | 技术栈锁定 Java 21、Spring Boot 4.0.7、React 18、Vite 6，与仓库技术栈说明一致。版本不写范围 | 仓库 `CLAUDE.md` 技术栈节 | 全部 spec §2 |
| D-010 | 首版连接器只做 PostgreSQL、MySQL、REST。不接 SAP、消息流、对象存储业务表 | 连接器每加一种都要有探测、权限编译、失败码。三种够支撑第一批业务系统 | spec-dat-source |
| D-011 | 业务逻辑扩展首版是 HTTP 钩子，页面模式里禁止可执行脚本。进程内 Java 钩子不做 | 见 D-018。页面脚本容易漏掉租户条件 | spec-pkg-install、spec-ui-schema |
| D-012 | 密钥只存引用号，引用指向 gnex 凭证服务。清单、日志、页面模式里不出现密文或明文 | gnex `credentials` 为受保护服务 | spec-svc-catalog、spec-dat-source |
| D-013 | 菜单不单独存储，由已发布路由生成 | 两份导航会漂移。停用路由必须同时从菜单消失 | spec-app-router |
| D-014 | 服务目录与 gnex 进程内服务键分账。基座服务键一律前缀 `biz.`，禁止与 `tenant`、`auth`、`agentLoop` 等同名 | gnex `05-interface-relationships.md` 已占用这些键，跨进程还禁止 Ctx 注入 | spec-svc-catalog、spec-brg |
| D-015 | 标准安装包（1 个实体、1 个列表页、1 个表单页、无外接源）从提交到路由可打开，时限 60 秒 | 设计目标，用来卡住「能装但要人守一夜」。复决：连续两周中位安装超过 90 秒则重开事务切分 | spec-pkg-install |
| D-016 | 跨源拼接估算行数超过 10000 直接拒绝，不降级为慢查询 | 慢查询会拖垮连接池，表现为页面卡死。拒绝比拖死可读 | spec-dat-query |
| D-017 | 评审发现必须回写本日志或审计记录，不允许只改正文不留异议 | 选型深度来自被反驳的记录 | 08-审计 |
| D-018 | 首版不在进程内加载业务 jar。钩子若要做，只能是指向已登记 `biz.` 服务的 HTTP 调用 | 设计。进程内加载在事务回滚后类仍留在进程里，也能自建连接绕开租户变量。复决：出现可按租户卸载的类加载器，且钩子拿不到数据源和桥接，才重开进程内钩子 | spec-pkg-install |
| D-019 | 托管表的行级策略同时约束租户和项目。缺项目与缺租户一样拒绝 | 设计。gnex 令牌含 projectId，串项目按租户规格同样是事故 | spec-dat-query、spec-idn-context |
| D-020 | 平台管理员是令牌 `roles` 里包含配置项所指角色名的人。不新增 `platformAdmin` 字段 | 设计。gnex 认证规格把权限放在 roles 声明里 | spec-brg-gnex、spec-idn-context |
| D-021 | 外接数据源整份归登记它的租户。源上没有租户列时，查询不拼接租户条件，也不假装对方库有行级隔离 | 设计。不能改客户表结构，又不能把 PostgreSQL 策略套到 MySQL 或 REST 上 | spec-dat-source、spec-dat-entity |
| D-022 | 只有安装状态为成功时，同一幂等键才回放第一次结果。已回滚或未提交必须允许再执行 | 设计。否则进程在提交前被杀死后，这把钥匙永远不能重试 | spec-pkg-install |
| D-023 | gnex 核验不可用时，除健康检查外全部拒绝。不读取页面缓存 | 设计。缓存成功凭证等于核验挂了还能看数据 | 总体设计、spec-idn-context |
