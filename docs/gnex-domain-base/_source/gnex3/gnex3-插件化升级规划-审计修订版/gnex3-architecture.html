GNEX3.0 插件化升级：对比 dsh · 融合设计 · 分层插件架构

以 DeepSeek Harness（dsh，Cordis 一切皆插件）为镜，重构 GNEX（Java/Spring 企业级 Agent OS）：服务是部署单元，插件是组合单元——9 个微服务与企业特性（多副本/弹性/租户/记忆 SoR）全部保留，服务内部由 cordis-jvm 插件内核组合能力。本页呈现三张架构图、81 个插件定义、映射关系与接口关系。

00总览：一页读懂 GNEX3.0

GNEX3.0 = 企业骨架 + dsh 组合语义。左边是现状（能力=代码模块，改能力=改代码+重构建+重启），右边是目标（能力=插件，装配清单组合，装卸不动骨架）。

04接口关系：事件总线与影响域

事件词汇对齐 dsh「域/动作」命名；进程内 waterfall/emit 由 cordis-jvm 提供，跨服务经 bus 插件发布到 RocketMQ topic。故障影响半径：L0/L1 内核 = 全服务，L3 能力 = 会话级，L4 企业 = 全平台（🔒 平台级升级+灰度）。

05企业特性保留清单（E1-E36 · 全部继承）

GNEX3.0 插件化不放松任何企业红线：多副本/弹性/租户/记忆 SoR/完成门/审批地板保持平台层；红线能力为受保护插件。
