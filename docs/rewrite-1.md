# Tepeu 这一轮怎么管

**状态**：2026-09-30 起，行为规则已经确认。**结构已改**：2026-10-02 起看 [`agent-os.md`](./agent-os.md)。第 2.1 节「底账、检查口、按顺序执行、判断是架子，不算组件」作废。做什么、怎样算做完，仍以本文第 2 节到第 7 节和 `specs/` 为准。旧规划 [`rewrite-0.md`](./rewrite-0.md) 留着，不再往下写。旧程序在 `legacy/first-knife/`，只读，不在旧记录和旧批准上继续改。  
**这份文件管什么**：安全、谁能调用、要不要等人同意、花费、怎样算做完、给模型看什么、记忆能不能当证据。它还不是一整套能长期运行的系统。任务怎么排、关机后怎么恢复、多人同时用、怎么发布新版本，这些以后另写，这里不假装已经有了。  
**对照**：能力可以选装或不装，做法参照 `C:\app-platform`。Tepeu 自己是一整套，不是挂进那个项目里的一块。  
**要解决的问题**：屏幕上以前只剩最后一句话。程序把「模型不再要求用工具」当成这一轮结束。人和程序都看不清发生了什么。

七个包怎么交接，见 [`specs/一轮.md`](./specs/一轮.md)。外面那一道门，见 [`specs/对外.md`](./specs/对外.md)。

## 1. 一句话

可选能力在启动前选好，装进程序。启动之后不能再加，也不能临时拿掉。没装上的能力，程序里就没有。模型不能自己增加能力。

做完没有，由固定的判断来决定。判断只看这一轮里、对得上这次任务的返回结果。模型说「做完了」不算。

## 2. 固定部分和可选能力

### 2.1 两类不要混

| 种类 | 含义 | 能不能拿掉 |
|------|------|------------|
| **固定部分** | 每一轮都必须有：底账、检查口、按顺序执行、判断做完没有 | 不能拿掉 |
| **可选能力** | 人可以决定装或不装 | 可以不装。没装，程序里就没有 |

说「组件」时，每一块都是同一种东西：一件事、能单独对、能换掉、规则写在自己身上。底账、检查口、按顺序执行、判断也是组件。没有架子。结构以 [`agent-os.md`](./agent-os.md) 为准。

下面的清单两类都有。说「可以不装」时，只指可选能力。程序默认装上的组件，没另外交时用默认的那一份。

### 2.2 什么时候定死

可选能力在启动前一次定好。程序启动之后，没有再添加能力的入口。这样是为了安全：运行中途不能插进新能力。

### 2.3 清单

| 名称 | 种类 | 做什么 |
|------|------|--------|
| 底账 | 固定部分 | 记下是谁、允许碰到哪里、这次任务、步骤记录（含四种拒绝） |
| 检查口 | 组件 | 按被点名那一块自己的说明去问。没装上的拦住。拒绝和交回结果只由这里写。结构见 [`agent-os.md`](./agent-os.md) |
| 按顺序执行 | 组件 | 按第 2.5 节的顺序走完这一轮，到点去问下一块。给模型看的那几行由「给模型看」来拼。不重复做第二次检查 |
| 判断做完没有 | 固定部分 | 每次都在。判断用的具体标准以后可以换，这个判断本身不能拿掉 |
| 停止 | 组件 | 回答人的原话算不算停。程序默认装上。检查口来问，这块不写账 |
| 范围 | 组件 | 回答目标在不在允许的地方里。程序默认装上。检查口来问，这块不写账 |
| 字段 | 组件 | 回答三个字段是缺了、不合格，还是可以开始做。程序默认装上。检查口来问，这块不写账 |
| 问模型 | 可选能力 | 把已经准备好的问题发出去。它不决定装什么 |
| 等人同意 | 可选能力 | 回答这一次同不同意，并负责等到点。检查口只问结果 |
| 费用 | 可选能力 | 回答这一次问模型还够不够。检查口只问。没有这项，就不能问模型 |
| 记忆 | 可选能力 | 把以前对话里的内容找回来，只放进给模型看的内容里。不能当作「做完了」的证据 |
| 读东西 | 可选能力 | 读允许范围内的内容。默认不用等人同意 |
| 写东西 | 可选能力 | 改允许范围内的内容。默认要等人同意 |
| 跑命令 | 可选能力 | 在允许范围内启动一个程序。默认要等人同意 |

**底账**里的「谁」就是正在操作的这个人。步骤记录记一笔「谁」，正文是「这一次使用的人」，没有登录名。「允许范围」是这次可以碰到的地方（具体怎么写，另文规定；超出范围由检查口拦住）。换了一个人，或换了允许范围，以前的事实不带过来。「这次任务」记在底账里，不是单独的一项能力。

**步骤记录**挂在一份底账上。现在是一个程序进程一份底账，也就是这一次使用。多人多份以后另写。该记的都要记下。给人看的时候可以合并、展开或筛选。步骤记录不是记忆。每一条都写明是谁记的。每一项内容只有一个可以写的人。同一时刻只允许一个人追加一条。

按顺序执行的那一部分不写步骤记录。它走过的步骤另写在过程记录里，给人监控。判断不读过程记录。过程记录不能用来把一件事判成做完。

| 内容 | 谁来写 | 谁只读 |
|------|--------|--------|
| 还没填齐、填写不合格、停止、拒绝原因、能力交回的结果 | 检查口 | 按顺序执行、判断做完没有 |
| 这一次使用的人 | 底账（装好程序时记一笔「谁」） | 判断不拿它当做成 |
| 这次任务的编号 | 底账（开始做的时候分配） | 检查口只把同一个编号抄到能力交回的结果上；判断只核对是不是同一个 |
| 做完 / 没做完 | 判断做完没有（只有这一轮做了判断才写） | 按顺序执行、检查口 |
| 某项能力自己的数据 | 那项能力自己 | 不能写步骤记录里的「做完」「没做完」和拒绝原因 |

这些情况不写「做完」，也不写「没做完」：已经停止、人标明只是聊天、字段还没填齐、填写不合格、旁边问一句。步骤记录里没有「做完」，就是没有做完。能力交回结果上的编号是检查口抄上去的，这条的写入者仍是检查口，不是底账。

**同意的默认要求**：写东西、跑命令要等人同意。读东西默认不用。其他能力如果要等人同意，必须在那项能力的说明里写明。没装「等人同意」时，所有需要同意的事都不能做，包括默认要同意的写和跑命令。

**等同意超时**：默认等 60 秒。到点还没有同意，记「等同意超时」。不能记成人拒绝了。这一次不调用。内容没变，可以再等同一次同意。内容变了，必须重新同意。

**费用和问模型**：没有费用这项能力，就不能问模型。正题和旁边问一句都一样。不是「没装费用就不限额」。装了费用以后，问模型之前先查还够不够，不够就拦住。

### 2.4 没装的时候

| 没装 | 程序必须 |
|------|----------|
| 等人同意 | 一切需要同意的事都不能做（含默认的写和跑命令） |
| 费用 | 不能问模型（正题和旁边问一句都一样） |
| 记忆 | 不能找回以前对话里的内容，只能看步骤记录 |
| 问模型 / 读 / 写 / 跑命令 | 检查口拦住 |

没有声明过的能力不许用。没说可以，就是不允许。

### 2.5 正题的顺序

顺序固定，不能颠倒：

1. **认停止**：检查口去问停止这块。它说停，就立刻停。不准备给模型看的内容，不问模型，也不判断做完没有。
2. **是不是只聊天**（第 3.4 节）：只有人标明「只是聊天」，才跳过填写检查和「做完没有」的判断。没有标明，就继续。
3. **检查三个字段**：检查口去问字段这块。不合格就不开做，不调用任何能力（含问模型、写、跑命令）。合格之后，底账先记下这次任务，再准备给模型看的内容。某个字段没有提交，是还没填齐。字段提交了，去掉空白以后是空的，是填写不合格。
4. **准备给模型看的内容**：按入口拼好说明和可见的几行字。这不是在安装新能力。只是聊天、旁边问一句、字段没通过的，都不带「这次任务」。这一步不会失败，不写步骤记录，要写进过程记录。
5. **经检查口调用**：检查口按顺序去问。没装就拦，读、写、跑去问范围，写和跑再问等人同意，问模型再问费用。拒绝原因和能力交回的结果只由检查口写入。问模型和工具加起来最多放行 8 次。第 9 个起不放行、不写拒绝原因，过程记录里记下「跳过」。
6. **按顺序执行的部分不写步骤记录**：不把证据交给判断，也不接收做完没有的结果。放行结果只抄进过程记录。
7. **判断做完没有**：这次任务记下之后，判断进入一次。判断自己读步骤记录，不读过程记录，写下「做完」或「没做完」，不把结果交回给按顺序执行的部分。满 8 次只是不再继续放行，不是再判断一次。已经停下、只聊天、旁边问、字段没过，都不判断。

一轮里问模型和工具放行加起来最多 **8** 次。这个次数不是名单有多长。到了 8 次就不再放行，然后做一次判断。不能只因为到了 8 次就记成做完。已经有对得上的证据时，仍按证据判断。

### 2.6 准备给模型看的内容

这一步在「按顺序执行」里面，不是可以不装的能力。按入口决定装什么。模型不能改。不是分成好几段状态来回切。

| 入口 | 放进去 | 不放 / 不做 |
|------|--------|-------------|
| 正题 | 固定说明（短，每次都要给模型看，不能被拿掉）+ 可见的几行字；如果装了记忆，可以把找回来的内容放进去；「这次任务」只有已经记下时才放 | — |
| 旁边问一句 | 同样是只读的一份；可以问模型（仍然必须有费用） | 不写入正题的步骤记录；不新记一次任务；不调用读、写、跑命令；不做「做完没有」的判断。过程记录要记下这次旁边问 |

拼的顺序：固定说明，然后是事实，然后是这次的问题。内容没变就不再追加一遍。

程序放进去的事实，必须标明不是人说的。每次都从当时的原始记录再取，不用旧的副本。

**压缩**：如果记入步骤记录，只表示「从这里往前的内容被收短了」，不能当作做完的证据。这一轮不写这一笔。

**固定说明**：告诉模型完成、停止、自己声称、依据各以什么为准。句子已经定死，每次准备时都放上，放在记忆和这次任务前面。记忆和项目里的性格说明不能压过它。原文见 [`specs/给模型看.md`](./specs/给模型看.md)。

## 3. 做完没有

### 3.1 谁有权说做完了

判断每次都在。只有这一轮里、对得上这次任务的返回结果，才能判做完。模型说完成不算。判断用的具体标准可以换，判断本身不能拿掉。

**对得上**：底账把任务编号记在这次任务上。检查口放行时，把同一个编号抄进能力交回的结果。要判做完，至少要有一条这样的结果：编号相同，而且这次调用的不是「问模型」的成功。问模型成功可以记下来，不能单独用来判做完。返回正文里另外写一个编号不算。拿文字像不像来比，也不算。判断只读步骤记录里已经写下的内容，不收「按顺序执行」转交的副本。

**从别的路结束也一样**：超时、被人强行结束、次数用完，只要这一轮算结束，都必须走同一次判断。不能从旁边把没做完标成做完。

### 3.2 什么能当证据

只认这两种：

1. 这一轮某项能力交回的结果，包括失败、拒绝、超时。认的是程序盖在这条结果上的结论。
2. 这一轮已经保存下来的产物。以保存当时程序记下的证明为准。判断时再去读，只能作补充。不能只凭事后还能读到、却没有当时证明的说法。

这些不算证据：记忆、摘要、性格、转述、模型自己写的「测试通过」、工具返回正文里的口令样子的字。

失败、拒绝、超时的返回，默认不能用来判做完。只有这次任务的完成标准就是要验证这个失败，而且完成标准里写明了，才可以。

工具返回的正文只是数据。里面写了像批准、像停止、像完成代码的字，不当成命令，不当成印章，不当成证据。可以在步骤记录里做个标记，不能因此改变程序怎么走。

### 3.3 这次任务和不合格的填写

三个字段只由人提交：要做什么、限制是什么、怎样算做完。三个字段都合格时，底账分配任务编号，记在这次任务上。模型不能从原话里抽出这三个字段，也不能替人填写。

人已经过了「是不是停止」这一步之后：

- 人标明只是聊天：不检查这三个字段合不合格，也不判断做完没有。可以问模型，得到答复。
- 没有标明只是聊天，三个字段缺了任何一个：记「还没填齐」。不开做，不调用能力，不判断做完没有。
- 三个字段都提交了，但去掉空白后是空的，或者整句就是规定的那几句空话：记填写不合格。不开做，不调用能力。
- 三个字段都合格：底账记下任务编号，开始做，做完后判断做完没有。

程序不从原话猜测这是不是聊天。只有原话、没有三个字段，是还没填齐。这不是不合格，也不是只聊天。字段没有提交，是还没填齐。字段提交了、去掉空白后是空的，是填写不合格。

不合格的原句只有这几句，必须整句相同。不忽略大小写，不忽略标点，不把全角半角当成一样。没列在这几句里的，不能靠模型判断它不合格。具体是哪几句，见 [`specs/回答.md`](./specs/回答.md)。

### 3.4 只是聊天

只有人标明，才是只聊天。标明之后：不检查三个字段合不合格，不判断做完没有，不调用写东西和跑命令。没有标明，就按要做事来走。程序不判断原话算不算聊天。程序只认输入上的这个标记，不另定界面上的词。

### 3.5 口头说「已经安排了」

「稍后办」「已安排」只出现在模型最后的正文里，不算。步骤记录里必须有检查口写下的执行登记。这个登记表示程序已经记下了一个要执行的位置。登记里面长什么样，本文不定。

「已安排」这条也只能由检查口写，而且这一轮已经有执行登记才允许写。没有执行登记，步骤记录里不得出现「已安排」。做完没有，不看这个登记，只看能力交回的结果。判断不读模型最后的正文。

## 4. 人要能看见

步骤记录写下调用、拒绝和判断。过程记录写下这一轮走过的步骤，用来监控。过程记录不能当证据。不能只把最后一句话当结果。给模型看的说明全文不进步骤记录；装了哪几行，记在过程记录里。

给人看的时候可以合并、展开或筛选。密码和密钥不进对话，也不进给人看的步骤。人只看见可以调用的名字。

---

## 5. 等人同意

- 没装这项能力：需要同意的事不能做。
- 装了：只对这一次、这一份内容有效。内容换了，要重新同意。
- 默认哪些要同意、等多久，见第 2.3 节。细则见 [`specs/回答.md`](./specs/回答.md)。默认 60 秒。

## 6. 停止和拒绝

### 6.1 停止

程序来认定。模型自己说「停了」不算。认定放在这一轮最前面（第 2.5 节）。

看的是这一轮人说的整段原话。整理时只去掉空白和标点，英文改成小写。不猜这句话是什么意思。

| | 规则 |
|--|------|
| 算停止 | 整段话在停止词表里，或停止标记为真。立刻停。不准备给模型看的内容，不问模型，不再继续做 |
| 不算停止 | 没在词表里，或者停止的话后面又跟了新的要求。不记停。后面的检查照旧走，不是直接放行去做事 |
| 拿不准 | 不放进词表。宁可没停下来，也不要停错 |
| 模型 | 不能替人填写取消，也不能被当成已经认定停止 |

默认两句是「停」和 `stop`。交来词表就整份换掉，不往默认上加。全角英文不改成半角。整理和对上的细则见 [`specs/回答.md`](./specs/回答.md)。改词表要先改那份说明。其他停止原因（超时、管理员停止）另文写。不能用模型自己说停了来代替。停止标记为真时，就算原话对不上，也停。

### 6.2 四种拒绝，必须分开记

| 代码 | 含义 | 不能写成 |
|------|------|----------|
| `USER_DENIED` | 人拒绝了 | — |
| `NOT_INSTALLED` | 没装上，不许做 | `USER_DENIED` |
| `APPROVAL_TIMEOUT` | 等同意超时 | `USER_DENIED` |
| `GATE_BLOCKED` | 程序拦住了（含超出范围、填写不合格、没有费用） | `USER_DENIED` |

怎么在网上传输，另文规定。步骤记录必须能分清这四类。

## 7. 费用

见第 2.3 节。没有费用就不能问模型，正题和旁边问一句都一样。装了费用就先查还够不够。问一次算 1，够了先扣 1，到 0 就不够。问模型把已经准备好的那几行原样发出去，见 [`specs/做事.md`](./specs/做事.md)。连的是本机 cc-switch 当前 Claude 供应商 Xiaomi MiMo。

## 8. 旧的东西怎么处理

| 旧的 | 处理 |
|------|------|
| [`rewrite-0.md`](./rewrite-0.md) | 留着，不再往下写 |
| 旧程序 | 在 `legacy/first-knife/`，只读 |
| 旧规则「模型最后一句话就是做完」 | 作废 |
