# 易可图AI改图

## 1. 目标与适用范围

根据用户提供的图片和自然语言改图要求，调用易可图 MCP 创建 AI 改图任务、查询结果，并将真实生成图片返回给用户。

适用于：

- 换背景 / 换场景；
- 去除或修改画面元素；
- 调整颜色、构图或视觉效果；
- 去文字 / 改文字等自然语言改图需求；
- 基于同一张原图生成多个改图版本。

如果用户的目标是“生成一整套商品图 / 白底图 + 场景图 + 卖点图 + 细节图”等完整套图，应优先使用商品套图 Skill，而不是本 Skill。

---

## 2. 规则优先级

执行时遵循：

1. **用户明确要求决定改图目标**：不得擅自增加用户未要求的重大修改。
2. **运行时 MCP `inputSchema` 决定参数是否合法**：类型、required、enum、数量范围、字段结构均以当前 Schema 为准。
3. **本 Skill 决定业务执行方式**：包括默认生成数量、Prompt 整理、重试、查询和交付方式。
4. **业务事实必须有真实来源**：商品属性、点数、价格、任务状态、成功数量等不得自行推测或估算。

MCP description 或示例中的示范值只用于理解接口，不得直接当成用户任务的默认值或真实业务数据。

---

## 3. 标准执行流程

```text
理解用户改图需求
→ 获取原图
→ 如为本地/附件图片，转换为接口可使用的图片 URL
→ 整理 prompt 和生成数量
→ saveAiImgPromptEditTask
→ 获取 taskId
→ getAiImgPromptEditTaskList 查询任务
→ 核验真实结果
→ 返回生成图片 + taskId
```

用户明确要求取消任务时：

```text
cancelAiImgPromptEditTask
```

不要主动取消用户任务。

---

## 4. 图片与参数规则

### 原图 `baseImgUrl`

必填。

图片需满足当前接口要求：

- JPG / PNG；
- 单张不超过 10MB；
- 宽、高均大于 14px；
- 总像素不超过 36,000,000；
- 宽高比范围 1:16 ～ 16:1。

如果用户提供的是本地图片或 WorkBuddy 附件，应复用易可图现有上传能力，将图片转换为接口可使用的 URL 后再创建任务。

如果用户已经提供可直接使用的图片 URL，则按当前运行时 MCP 说明执行；不要自行假定“所有公网 URL 都必须重新上传”或“所有图片都必须是易可图 OSS”。

### 生成数量 `imgNum`

范围：1～4。

- 用户明确指定数量：严格按用户要求；
- 用户未指定：默认 `1`；
- 不得为了“多给几个方案”擅自增加数量。

如果用户要求超过 4 张，应说明当前单次最多支持 4 张，并让用户调整数量或拆分任务；不要擅自创建多个收费任务。

### 改图指令 `prompt`

必填，不超过 500 个汉字。

应：

- 保留用户原始改图意图；
- 简洁、明确地描述需要修改的内容；
- 必要时补充“保持商品主体一致”等与用户目标直接相关的约束。

不得：

- 擅自增加用户没要求的改动；
- 虚构商品材质、性能、尺寸、认证等事实；
- 为了让 Prompt “更丰富”而改变商品结构、颜色、配件或功能。

例如用户说：

> 把背景换成圣诞客厅，商品不要变。

可整理为：

> 将背景替换为圣诞客厅场景，保持商品主体、颜色、结构和外观不变，商品清晰突出。

---

## 5. 商品事实与计费事实

所有业务事实必须有明确来源。

可信来源包括：

1. 用户明确提供的信息；
2. 当前 MCP / 易可图接口真实返回的信息；
3. 当前上下文中明确提供的易可图官方规则；
4. 图片中可以直接观察到的视觉事实。

仅凭图片不得自行确认：

- 材质、成分；
- 防水、耐用、可机洗等性能；
- 尺寸、容量、承重；
- 功率、续航、兼容型号；
- 认证、质量等级。

### 点数、价格与折扣

当前 MCP / 接口如果没有返回真实点数或价格信息：

**不得估算、推算或编造具体点数、单价、折扣、预计消耗或节省金额。**

禁止说：

> 10点/张  
> 4张大约40点  
> 少生成2张可以省20点

如果用户询问具体扣点，而当前没有可靠数据，应说明：

> 当前 MCP 没有提供本次任务的具体点数消耗，无法准确计算或估算。

## 6. 查询、取消与异常处理

### 查询任务

创建成功并取得 `taskId` 后，使用 `getAiImgPromptEditTaskList` 查询真实状态。

支持状态：

- `wait`
- `processing`
- `success`
- `fail`
- `cancel`

查询频率遵循当前运行时 MCP 说明；如工具未明确查询间隔，不要高频连续轮询。

### 成功

只有任务真实返回：

```text
status = success
```

且存在有效的 `resultImageList` 时，才向用户交付生成成功结果。

结果图片链接有效期为 7 天，应提醒用户及时保存。

### 失败

如果：

```text
status = fail
```

如实告知任务失败，并附带 `taskId`。

如果接口未返回失败原因，不得自行编造原因。

不得未经用户同意自动重新创建收费任务。

### 取消

只有用户明确提出：

- 取消；
- 停止；
- 不要继续生成；

才调用 `cancelAiImgPromptEditTask`。

取消结果以 MCP 实际返回为准。

### 参数或上传错误

如出现参数结构、Schema 或上传错误：

1. 根据当前 MCP 说明检查并修正；
2. 最多正常重试一次；
3. 仍失败则停止。

不得长时间反复调试或不断创建新任务。

### 点数不足

如果 MCP 明确返回点数不足：

- 立即停止；
- 告知用户当前账号点数不足；
- 不自行推算还差多少点；
- 不擅自减少图片数量、修改要求或偷偷重试。

---

## 7. 用户沟通

正常执行保持简洁。

不要向普通用户展示：

- STS；
- OSS Key；
- signature / token；
- MCP Schema；
- 参数序列化；
- 内部调试过程。

应向用户提供：

- 必要的缺失信息确认；
- `taskId`；
- 真实任务状态；
- 最终生成图片；
- 失败或取消结果。

任务创建成功后可告知一次 `taskId`；最终交付时必须附带 `taskId`，便于追溯。

---

## 8. 禁止行为

禁止：

1. 擅自扩大用户改图范围；
2. 用户未指定数量时自动生成多张；
3. 用户要求超过 4 张时擅自拆成多个收费任务；
4. 虚构商品材质、性能、尺寸、认证等事实；
5. 虚构或估算没有真实来源的点数、价格、折扣；
6. 任务失败后未经用户同意自动重建任务；
7. 用户未要求时主动取消任务；
8. 接口未返回失败原因时自行猜测原因；
9. 高频轮询任务状态；
10. 未取得真实结果时声称改图已经完成。

---

## 核心原则

**用户要求决定改什么。**

**MCP Schema 决定参数是否合法。**

**未指定数量默认 1 张。**

**业务事实必须有真实来源。**

**商品属性、点数、价格、任务状态都不得脑补。**

**失败不无限重试。**

**不未经用户同意重复创建收费任务。**

**只有真实成功后才交付成功结果。**
