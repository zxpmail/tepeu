# 番知会员查询与洞察

只使用用户确认的 `target_shop_id`。没有确认店铺时先调用 `mcp_access_context_list`；调用前检查所需工具是否在该店铺的有效能力中。所有输入按当前工具 Schema 生成。

开始前必须先读 [总入口的最高优先级单项失败隔离、输出闸门与调用前置](../fanzhi-ticketing/SKILL.md)，用完整权限码检查当前店铺。实际能力还受查询计划、数据量预算和隐私分桶约束。

## 工具选择

- `member_search`：用会员 ID、会员号或完整手机号精确定位会员。
- `member_get`：用已确认的会员 ID 查询概要和资产摘要。
- `member_profile_report`：查询组织级会员标签、性别、年龄段和省份聚合；默认是组织全量会员，可按注册时间区间只看区间内新注册会员的性别、年龄段和省份。
- `member_insight_report`：查询标准时间窗口或指定期间内的会员增长、地域、年龄、购买偏好和净消费分布。

## 关键参数

- `member_search`：必填整数 `target_shop_id`，并至少提供整数 `member_id`、字符串 `member_no` 或数字 `mobile`；`limit` 默认 10、最大 20。手机号按完整号码等值匹配，不支持号段或部分号码；允许 6～11 位只是为了兼容港澳等非 11 位号码。用户只给了部分号码时请其提供完整手机号。
- `member_get`：必填整数 `target_shop_id` 和已确认的整数 `member_id`。
- `member_profile_report`：必填非空 `dimensions` 和固定值 `report_scope=organization`；维度可选标签、性别、年龄段、省份，`top_n` 默认 20、最大 100。`tag_types` 只用于标签维度。可选 `period`（自然月、自然年或最长 366 天自定义），只在用户要看某段时间新注册会员时传，且不能与标签维度同传。
- `member_insight_report`：`window`（3、7、30、90、180 天标准窗口）与 `period`（自然月、自然年或最长 366 天自定义）必须且只能传一个；未指定 `dimensions` 时服务端默认返回增长、地域、年龄、偏好、消费五类聚合。

## 用户表达

- 工具名、字段名、枚举值、内部 ID 参数、原始 JSON、Schema 和错误码仅供内部调用，普通回答中不得展示。
- 用“请提供会员号或完整手机号”“请选择要查看的会员”“你想看哪个时间范围”等自然语言澄清，不向用户索要参数名。
- 会员状态、等级、统计维度和告警转换为可读中文；个人候选始终脱敏。无法查询时采用总入口的友好文案，并给一个可执行下一步。
- 服务端已脱敏的字段原样展示，不得还原、拼接或推测完整值；本 Skill 不另行假定固定掩码格式。

## 会员点查

1. `member_search` 至少提供 `member_id`、`member_no`、`mobile` 中一个精确标识；不要按昵称、标签或日期扫描。
2. 多个标识冲突或返回多个候选时，让用户确认，不默认第一项。
3. `member_get` 必须传已确认的 `member_id`；失败时按总入口隔离该项，不自动改用 `member_search` 回查。未找到时请用户核对标识，不猜 ID。
4. 手机号和会员号保持服务端脱敏；本连接器不应返回证件号、登录 IP 或地址，也不得尝试补全。

## 聚合报表

- `member_profile_report` 必须传用户需要的 `dimensions` 和固定的组织级 `report_scope`。它只按本工具权限授权：目标店铺的有效能力包含 `mcp:tool:member_profile_report` 即可调用，不要求主店超级管理员，也不看两个组织报表能力标记。会员是组织级资产，结果始终覆盖目标店铺所属的整个组织，回答时要说明这是组织整体数据、不是本店数据。
- 画像不传 `period` 时是组织全量会员；传 `period` 时性别、年龄段、省份只统计区间内新注册会员（响应的样本口径会标明），回答必须写清是“全部会员”还是“某期间新注册会员”。标签是全量人数快照，不支持时间段：用户同时要“某期间新会员的标签”时，说明标签只能看全量，分开回答，不把全量标签套到新会员上。
- 画像工具没有 `shop_ids` 参数，不能按店铺筛选。标签维度和自然人属性维度覆盖人群可能不同，各维度占比使用自己的分母，不能跨维度直接比较。
- `member_insight_report` 的“近 N 天”只有 3、7、30、90、180 天标准窗口；其他天数、某个月、某一年或具体起止日期用 `period`，最长 366 天，不能用相近窗口冒充。区间内新增或消费人群超过 20 万时会被拒绝，请用户缩短区间，不自动拆分多次查询。
- 只有 `member_insight_report` 可使用 `shop_ids`，且仅在组织范围查询时可传；它只缩小消费群体（偏好、消费），新增群体（增长、地域、年龄）始终按全组织统计。按店铺看洞察时必须说明新增群体不是该店口径。不得把单店授权提升为组织报表。
- 洞察的 `new_member_cohort`（新增群体：增长、地域、年龄）与 `purchasing_member_cohort`（消费群体：偏好、消费）是不同分母，必须分开说明。未请求的维度可能返回空数组，这不表示人数为零。
- 消费偏好支持产品类型和项目分类。只在用户需要偏好维度时传相应选择；项目分类中的“未分类”是服务端保留的真实分桶，不能丢弃。
- 城市或区县地域分组超过返回上限时，不自动降级重试；说明范围过细，并请用户改用省级或缩小范围。
- 保留服务端合并的小样本“其他”桶和隐私提示，不通过缩小范围、差分或多次查询还原被合并人群。响应的告警中出现小样本合并提示（`PRIVACY_BUCKET_MERGED`，目前用于洞察地域和画像标签）时，用中文说明“人数过少的分组已合并为‘其他’”，不展示告警代码。
- 画像与洞察只返回群体聚合，不能反推个人属性、给个人贴敏感标签或声称统计相关性是因果关系。
- 安全数据计划不可用时停止对应维度，不实时扫描会员和交易明细拼接。

## 典型问法与执行

以下箭头后的工具与参数只用于内部路由，不得在用户回答中复述。

- “查会员 ID 123” → `member_get`；未找到时请用户核对。用户提供的是会员号或手机号时，先用 `member_search` 定位。
- “查手机号 13800001111 对应的会员” → `member_search(mobile=...)`，只展示脱敏候选；用户只给了“138 开头”“尾号 1111”等部分号码时，先请其提供完整手机号。
- “看看这个会员的等级和资产” → 先确认会员 ID，再 `member_get`；不补查未返回的个人隐私。
- “查看组织会员标签画像” → 确认有效能力包含画像工具后调用 `member_profile_report(dimensions=["tag"], report_scope=organization)`。
- “查看全部会员性别、年龄和省份画像” → 确认有效能力包含画像工具后调用 `member_profile_report`，只选择用户要求的三个维度，并分别说明各自样本口径。
- “近 30 天会员增长和购买偏好” → `member_insight_report(window=last_30_days)`，只选择增长与偏好维度。
- “近 90 天会员偏好哪些项目分类” → `member_insight_report(window=last_90_days, dimensions=["preference"], preference_dimension=project_category)`。
- “8 月新增会员主要来自哪些省” → `member_insight_report(period=2026 年 8 月, dimensions=["geography"])`。
- “今年新注册会员的性别和年龄” → 确认有效能力包含画像工具后调用 `member_profile_report(period=今年, dimensions=["gender","age_band"])`，说明样本是今年新注册会员；不带标签维度。

## 多工具场景

- 会员标识→概要：`member_search` 定位后由用户确认，再 `member_get`。
- 会员→订单：确认会员 ID 后转入 `trade_search`，同时要求时间范围；不能用会员搜索结果绕过订单查询门禁。
- 群体画像和个体查询必须分开回答；聚合结果不能套到某个会员身上。

## 输出

- 读取 `result.structuredContent`，保留样本范围、窗口、维度、统计口径、新鲜度和告警。
- 空聚合明确说明该条件下暂无可用数据，不把缺失维度解释为 0。
- 个人查询按“脱敏身份 → 会员状态/等级 → 资产摘要 → 数据时间”组织；聚合报表按“范围与样本 → 维度分布 → 主要观察 → 口径/告警”组织。
- 不输出完整手机号、证件号或可用于重新识别个人的信息。
- 默认直接在对话中输出 Markdown，不创建文件。
- 用户明确要求“页面”、“HTML”或可下载产物时，只生成一个最终交付文件，直接使用 MCP 返回数据渲染。禁止创建中间 JSON、数据快照、构建脚本、校验文件、备份或其他辅助产物。
- 只在内部确认最终产物与当次返回字段一致，不另外输出创建文件、运行校验或修改脚本等过程记录。

## 失败处理

- 任一工具失败后只跳过该查询项及依赖步骤，继续其他独立会员查询，最后按总入口的“最高优先级：单项失败隔离与输出闸门”补充一条错误提示；不得展开工具、参数、Schema、权限详情或自动生成修改报告/文件。
- 按总入口 Skill 的错误映射恢复并输出用户友好文案；普通回答不得展示错误码、请求 ID 或底层异常。
- 会员或组织报表授权不足时不能改查个人明细绕过；查询或数据不可用时停止该报表或维度；限流仅在允许时按指定时间重试一次。
