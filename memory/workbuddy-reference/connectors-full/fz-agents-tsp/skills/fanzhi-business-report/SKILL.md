# 番知经营成果报告

本 Skill 只把当前 MCP 已返回的数据组织成可交付结果，不维护静态指标对照表，不预设“标准数字”，也不根据历史经验解释差异。

开始前必须先读 [总入口的店铺确认、权限检查、响应处理和单项失败隔离](../fanzhi-ticketing/SKILL.md)。只使用用户确认店铺的有效只读能力，所有参数按运行时 Schema 生成。

按本次所需查询读取对应领域规则：订单指标读 [订单](../fanzhi-trade/SKILL.md)，项目复盘读 [项目](../fanzhi-project/SKILL.md)，流水或服务费读 [财务](../fanzhi-finance/SKILL.md)，经营趋势或渠道统计读 [经营分析](../fanzhi-analytics/SKILL.md)。只读本次用到的领域，不跳过其期间、分页和指标限制。

## 三种交付模式

### 经营日报

1. 先确认统计日期或明确起止时间；用户只说“日报”但没有日期时，先询问日期，不自行选最近一天。
2. 订单核心指标使用订单收入汇总；用户明确要求商户实际收入、渠道销售、分销订单、当日退款明细或月度趋势时，再增加对应查询。不要为了填满模板调用全部工具。
3. 输出统计范围、核心结果、用户明确要求的分组结果和数据状态。没有查询的指标不占位、不估算。

### 项目复盘

1. 先确认唯一项目，再根据问题选择报表。
2. 指定期间的财务或渠道表现使用支持期间的查询；票档销售、出票类型、渠道与票档交叉报表属于项目全生命周期结果。两类数据必须分区展示，不得合并成同一期间。
3. 用户要求核销时，明确区分当前票码状态快照、已结束场次上座率和销售期间；不得把当前快照写成历史期间核销结果。
4. 结论只基于已返回字段。需要原因分析而返回结果没有原因字段时，写“当前数据只能确认现象，无法确认原因”。
5. 场次分页未取完时只展示当前已查询场次，不把当前页汇总写成全项目核销或总上座率。

### 结算对账

1. 单笔订单先确认订单，再查询对应财务流水；分别展示订单状态、支付或退款金额、流水状态和时间。
2. 期间服务费只使用服务费汇总结果，分开呈现应计服务费与实际分账金额；不得把两者相减后命名为差额原因。按项目对账时用服务费的按项目统计，并保留“部分分账找不到对应订单、未计入项目”的提示。
3. 订单状态、收入汇总、财务流水和分账状态是不同对象。只有返回字段中存在可关联标识时才关联，不按金额或时间猜测对应关系。
4. 当前没有逐笔分账明细能力。用户要求逐笔分账单号或状态时，明确说明当前连接不支持，不拼接其他数据模拟。

## 精简执行

- 默认直接在对话中用 MCP 返回数据生成最终 Markdown，不创建任何文件。
- 只执行回答问题必需的查询。自检仅确认结论、表格与当次返回字段一致，不另外输出中间校验记录。
- 禁止生成中间 JSON、构建脚本、校验文件、备份文件或额外 HTML。不为排版临时创建或修改 Python、JavaScript 等脚本。
- 用户明确要求下载文件或指定文件格式时，交付物也只能有一个：直接写入最终报告文件，不保留任何辅助文件。
- 最终答复只交付结果、数据范围和必要限制，不复述读文件、改脚本、运行校验等内部过程。

## B 端页面复核（仅按需）

只有用户明确要求“B 端页面对应”、“页面自检”或“页面复核”时，才读取 [B 端页面验证表](references/b-end-page-verification.md)并附上复核入口。普通日报、复盘和对账默认不读该文件、不附页面路由。

复核入口必须是可点击的完整 Markdown 链接，并分开显示“测试环境”和“正式环境”，不只输出相对路由。只在与本次数据同环境的页面核对；含项目 ID、订单号等路径参数时，使用已在对应环境确认的真实值，不能把测试标识直接套入正式环境。缺少参数时只写“需先确认对象”，不生成占位链接。

- A 级可以标为“直接对应”；B 级只能标为“业务对象可对照”；C 级写“暂无直接页面”。
- 没有实际访问页面并对齐筛选条件时，只能提供复核入口，不能声称“已与 B 端核对一致”。
- 自检必须对齐店铺、项目、时间字段、起止时间、状态、渠道和其他筛选条件。无法对齐时，保留差异并列出未对齐条件，不猜原因。
- 发现差异时记录报告值、页面值、筛选条件、生成时间、数据新鲜度和告警；不要套用静态差异说明。

## 输出要求

默认用 Markdown 输出，顺序如下；用户没有要求的部分直接省略：

1. 标题与统计范围：店铺、项目、日期或期间、生成时间。
2. 关键结论：只写已查询结果能够直接支持的结论。
3. 明细：按经营日报、项目复盘或结算对账的实际内容分组。
4. 必要统计说明：用业务语言保留影响结论的时间基准、筛选条件、有效更新时间和告警；不默认罗列技术字段、版本或缺失项，用户明确排障时再提供必要的脱敏信息。
5. 未完成项：只列失败或当前能力不支持的项目，并沿用总入口的友好错误表达。

用户明确要求 B 端页面复核时，再追加测试环境链接、正式环境链接、对应等级和需要保持一致的筛选条件。

按日分组只展示返回中实际存在的日期；缺行不等于零收入，不补零、不判定为数据故障。本月、本年按总入口规则写“本月累计”“本年累计”，不猜数据截止日、不例行添加未知更新时间说明；与完整历史月、年比较时注明“本期尚未结束，比较期间不等长”。

金额、数量、比例和时间的显示优先使用服务端单位与精度；服务端未提供换算规则时不自行换算。默认不创建 HTML、台账或其他附件；用户指定文件交付时也只生成一个最终文件。

## 失败处理

- 任一查询失败，只移除依赖该结果的结论与表格行；其余独立结果继续交付。
- 不用统计范围或业务含义不同的数据补空缺，也不把空数据写成零。
- 报告没有任何成功数据时，不生成空模板，只返回总入口规定的简短错误提示。
