# 198智能健康连接器 v3.3.3 技能说明（真数据·演示门版）

## 技能概述

本技能指导AI正确使用9两健康198智能系统连接器 **v3.3（真数据版）**。与此前版本的根本区别：**12 个工具全部直读 198 生产库实时数据**，不再有任何模拟/演示数据。连接器遵循四条设计红线：

1. **绝不编造**：查不到就显式报错或如实留空，任何兜底数据都以 `data_demo: true` 标注
2. **授权先行**：调阅任何客户健康数据前，先校验《健康数据授权同意书》签署状态（signed 才放行，否则 403 合规拦截）
3. **只读合规**：当前版本全部为只读查询；写操作返回 451「写通道待合规开放」，绝不接假成功
4. **演示内容不流向客户**：存量报告中凡属演示引擎渲染（正文含演示桥标识）的，正文与演示等级一律拦截不对外；改以九两八数精算基于客观指标现算等级（含单项熔断），客观指标与正式血统的结构化照护方案照给

## 核心能力（12个工具）

### 一、198评估核心（3个工具）

- **get_evaluation** · 获取198评估报告（真实）
  - 入参：`customer_id`（必填）
  - 返回：评估ID/报告状态/生成时间/风险等级/八数指标/care_plan 结构化方案（如有）
  - 报告血统判定：正式引擎报告→返回真实报告全文 Markdown+解析等级；演示引擎报告（正文含演示桥标识）→不返正文与演示等级，改返【九两八数精算】等级（服务端精算引擎基于客观指标现算，含权重覆盖度与单项熔断说明）+客观指标+正式血统 care_plan，响应带 `demo_gated: true`
  - 合规：客户未签署同意书 → 403 拦截（附合规提示）
  - 空态：客户无评估记录 → 如实返回"建议先完成评估建立基线"

- **get_daily_plan** · 获取个性化干预方案（真实 care_plan）
  - 返回七类分区任务：膳食/情志/睡眠/运动/随访/环境/经络（含内容/频率/依据/禁忌/提醒时间）
  - 数据为198评估报告生成的真实结构化方案，每条带证据来源
  - 空态如实：新版评估若 care_plan 未生成，返回"报告未生成有效结构化照护方案"（不编造任务）

- **get_health_trend** · 健康趋势分析（真实）
  - 粒度=历次评估（per_assessment），**非每日连续数据**（如实标注，不误导）
  - 支持指标：空腹血糖/餐后血糖/体重/收缩压/舒张压
  - 自动计算均值/改善趋势；数据点<2 时如实提示"积累中"

### 二、风险管理（2个工具）

- **get_risk_stratification** · 风险分层
  - 个人维度：等级取自**九两八数精算**五档（优秀/良好/注意/警示/高危）；
    演示桥渲染的报告走演示门后同样以八数现算等级为准，**不采用演示桥的等级口径**
    （如「基本正常·留意」）。算不出则不猜等级
  - 企业维度：按单位聚合真实风险分布（低/中/高/暂无报告四档），小样本合并，不编造占比

- **generate_enterprise_report** · 企业年度健康报告（真实聚合）
  - 按 employerName 聚合：在管人数/报告覆盖率/风险分布/Top10 单位钻取
  - 全部来自198生产库实时聚合， percentages 按真实计数计算

### 三、服务与运营（4个工具）

- **get_kqm_tasks** · 随访工作台（真实跟进记录）
  - 198 生产库 customer-follow-up 全量队列，按下次跟进时间排序
  - 自动标记优先级（逾期=high/3天内=medium）与逾期状态
  - 含真实跟进内容（如肠道菌群报告归档、复查提醒等）

- **submit_followup** · 提交跟进记录 ⚠️写通道暂缓
  - 当前返回 451：写通道待合规开放（会在生产库创建/修改数据）

- **recommend_products** · 产品推荐（真实服务包）
  - 目录来自 business/service-package 真实数据（名称/价格/说明）
  - 结合客户评估风险等级给出匹配理由（高/中/低/未知四档话术）

- **get_dashboard** · 运营数据看板（真实计数）
  - 生产库实时：客户总数/评估总数/报告总数/跟进总数/在售服务包数
  - 销售指标未对接商城，如实留空（不填 0 不编造）

### 四、数据合规（2个工具）

- **export_anonymized_data** · 脱敏聚合导出（k-匿名保护）
  - 性别分布/年龄均值等聚合维度
  - 任一分组 < min_group_size（默认5）即不出数（隐私优先）
  - 输出数据指纹（sha256）便于核验

- **create_evaluation** · 创建198评估 ⚠️写通道暂缓
  - 当前返回 451：写通道待合规开放

### 五、随访计划（1个工具）

- **schedule_followup** · 设置随访节点 ⚠️写通道暂缓
  - 当前返回 451：写通道待合规开放

## 注意事项

1. **医疗边界**：198系统输出为健康管理建议，不构成医疗诊断
2. **授权红线**：403 拦截是合规特性不是故障——引导客户先签署同意书
3. **粒度诚实**：健康趋势为"每次评估一个点"，非每日数据
4. **空态与演示门均属正常**：新版评估（2026-10起）care_plan 可能未生成，如实报告即可；
   演示桥渲染的报告走演示门（见第 7 条）——演示正文与演示等级拦截，
   但**风险等级照给**（九两八数精算现算）。
   **不得告知客户"无报告"或"等级暂不提供"** —— 治未病以风险判断为核心，缺失即误导
5. **写操作**：451 响应是合规设计，告知用户"写通道待合规开放"即可，不要重试
6. **数据时效**：看板/计数均为实时查询结果
7. **演示门**：响应含 `demo_gated: true` 时，正文与演示等级已被合规拦截，展示的是八数精算等级+客观指标+正式 care_plan，属正常行为

## 错误处理

| 错误码 | 说明 | 处理方式 |
|-------|------|---------|
| 400 | 参数错误 | 检查必填字段（如 customer_id） |
| 401 | 授权失效 | 检查 API Key（jlk_ 前缀，联系9两管理员签发） |
| 403 | 客户未签署同意书 | 合规拦截：先取得客户授权 |
| 404 | 记录不存在 | 客户无评估/方案未生成（如实空态） |
| 451 | 写通道待合规开放 | 写类工具合规暂缓，勿重试 |
| 502 | 上游198服务暂不可用 | 稍后重试 |
