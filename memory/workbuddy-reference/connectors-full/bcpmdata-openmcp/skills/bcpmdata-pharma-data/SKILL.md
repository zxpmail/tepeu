# 摩熵医药数据：兜底路由与调用思路

> 🎯 **定位：兜底，优先级最低。** 本技能只解决「怎么正确访问摩熵数据」这一层，不做业务流程。适用裁决：
> 1. 若存在更具体的已安装技能（如报告生成、专项分析、可视化流程）且覆盖当前任务 → **以那个技能为主干**，本指南仅在被问及数据从哪来、或那个技能需要选工具时作参考；不要把本指南的流程叠加到专项技能之上。
> 2. 若多个专项技能都部分匹配 → 选范围最窄、最贴合用户原话的那个，而不是本指南。
> 3. 仅当用户就是直接查数据、没有任何专项技能接手时 → 按本指南自主路由。
> 一句话：**专项技能管「做什么、怎么交付」，本指南管「数据怎么拿」；两者共存时听前者的。**

本连接器暴露 100+ 个医药数据工具（POST，返回结构化 JSON）。用户提问前需在连接器表单填好 API Key（`auth_mode: token`）；返回 401/403 时提示用户重新连接并填写有效 Key（获取：https://open.bcpmdata.com/guide/1.html ）。

> ⚙️ **第一原则：工具以运行时列表为准。** 服务端工具会持续增删改。本文不维护工具清单，只提供三样运行时拿不到的东西：**① 业务域地图**（这个问题该去哪个领域找工具）、**② 易混数据源的取舍规则**（几个都像的工具选哪个）、**③ 共性约定与实测坑**。动手前先扫一遍运行时 tool list，用工具自带的 description 确认参数；本文与它冲突时，信它。

## 拿到问题后的决策流程（自主路由时，即上方裁决规则第 3 条）

1. **认实体**：问题里有什么锚点——药品通用名？批准文号？受理号？登记号？企业？靶点/适应症？疾病？专利号？CAS/SMILES？医院/药店？器械注册证号/耗材代码？
2. **归领域**：问的是哪个业务维度（下文域地图）。
3. **辨路**：多个数据源都像时，查「易混辨析」。
4. **组装**：多数库是 `XxxList` 拿主键 → `XxxDetail/BaseInfo/子主题` 取详情的两跳结构；也有直接 `search` 查询的独立接口。主键必须来自列表返回，不能编造；工具描述里一般写明主键从哪个 List 获取。若用户直接给出规范主键（如"国药准字H…"、受理号、登记号、专利公开号），可先试详情接口，失败再回列表。

## 易混数据源辨析（本指南的核心价值）

运行时描述只说"我能干什么"，不会说"我和隔壁谁强"。重叠处的取舍规则：

- **「获批/上市」分三层**：只关心中国最终批文 → 批文域；关心审评过程/申报动态/受理号 → 审评域；关心美欧日英等海外批准 → 全球上市筛选域；关心国内全生命周期进度汇总 → 品种格局域。
- **「临床试验」分三入口**：按药/适应症/机构查中国试验 → 中国临床域；查美国注册试验 → 美国临床域；已锁定某在研药物、要看它全球的中美试验 → 全球研发域下的试验挂接接口。
- **「销售/钱」分三种口径**：国内终端卖了多少（医院/药店/网上，样本推算，元）→ 市场销售域；某药全球按企业的销售额（年报口径，含推测值）→ 全球研发域；中标价/中选价/挂网价 → 价格准入域（集采与招投标是两个库：国家/联盟集采批次看集采，省级中标价看招投标）。
- **「专利」分三体系**：全库专利检索、著录/法律/同族/引证/全文 → 医药专利体系（入口是专利检索列表，主键为专利公开号）；已上市药品的专利链接/登记、到期监控、橙皮书、欧洲 SPC → 上市药品专利体系（主键为品种 id）；仿制药申报时的专利声明（P类声明）→ 审评域。
- **「医院」分两库**：问临床试验资质（备案、伦理、遗传办、项目经验）→ 临床机构域；问基本盘（等级、性质、地址、科室）→ 机构资源域的医院大全。
- **「新闻/文献/指南」的检索方式**：有明确条件（企业+日期、标题、靶点）→ 结构化检索；话题式、模糊、自然语言（"最近减肥药行业有什么动态"、"语义找相关论文"）→ 带 RAG/语义/混合字样的接口，直接把问题传进去。
- **「交易」分两处**：要一笔授权/合作的结构化记录（交易双方、类型、预计规模、许可区域）→ 交易域；要看市场对某交易/事件的报道 → 新闻域（同上再分结构化与语义）。
- **「医保」看手里有什么条件**：拿着批准文号查该文号医保类别 → 批文域的医保详情；按药品名/目录版本/地区查目录本身与限定支付范围 → 医保目录库；要医保分类代码、本位码 → 医保代码库（或聚合编码库一次拿齐批文+说明书+医保+69码）。
- **「说明书」分三处**：正文段落（适应症/禁忌/不良反应全文）→ 说明书库；审方规则（DDD、毒麻精放标识、抗菌分类）→ 审方版说明书库；要一次拿齐批文+说明书+医保+69码 → 聚合编码库。

## 共性约定

- **分页**：列表类普遍有 `page`（从 1 起，多数必传），部分有 `page_size`（默认 10）。返回普遍含 `total` 与 `list`。
- **search 对象**：字段一般全部可选，字段名、类型与**枚举可选值**都写在运行时参数 schema 里——传枚举前先读描述里的可选值列表，别凭记忆造值。
- **日期范围**：日期类检索字段通常是 object，按 `{min, max}` 传。
- **主键命名惯性**：批准文号 approval_number、受理号 acceptances_number、登记号 registration_number、品种/记录 keyid 或 id、专利公开号 publication_number、物质id pedia_id、机构名/研究者名直接用名称。以运行时为准。
- **多语言**：海外数据字段常带 `_cn`/`_en` 对，向中文用户呈现时优先用中文字段。

## 实测坑（编写时的观察，服务端可能已变，以实际响应为准）

1. **深分页约 100 页封顶**：翻页超限返回空 list。结果集大时别硬翻，用更细的 search（规格/企业/省份/批次）分片。
2. **偶发空响应**：`total>0` 但 `list` 为空时，重试 1-2 次再下结论。
3. **销售类 `year` 过滤偶发失灵**：按年统计可先取全量再本地聚合。
4. **金额是字符串、单位为元**：展示前换算成万元/亿元并注明口径。
5. **字段常为空**：详情接口大量字段非必填，缺失就如实说「该库未收录」，禁止编造。
6. **OSS 临时链接约 5 分钟有效**（如专利全文 PDF）：拿到立即转达，不要缓存。
7. **个别库（尤其较新的交易/指南/语义检索类）的 search 字段可能与 description 声称的检索维度不一致**（疑似后端模板复用）：构造请求时以工具 description 正文为准，字段拿不准先发一条小请求试探，报错再按运行时 schema 修。

## 能力边界（不要硬凑调用）

本 MCP 是**结构化医药数据库**，不提供：企业财报与股价、指南/文献的全文正文（多为元数据与摘要）、实时交易行情、诊疗建议本身。问题超域时直接说明边界并给出最接近的可用数据。

## 输出与错误

- 呈现结果时注明来源库名与检索条件，嵌套对象提炼关键字段。
- 参数报错：按错误信息修 search 字段名/分页；缺主键回到对应 List 重新取。
- 任何情况下不在回答中回显用户的 API Key。
