# DxC 视觉计划

内部调用 DxC CLI 时只使用 PATH 中的全局入口：`dxc <参数>`。本 Skill 的版本是 `0.3.24`，
安装流程必须已经验证 `dxc version --json`、本 Skill 集和该版本完全一致。正常任务不得通过 npm、
npx 或其他包执行器解析 DxC，也不得硬编码任何用户的可执行文件绝对路径。若 `dxc` 不在 PATH，或
CLI 报告官方 Skill 版本不一致，停止并请用户按安装说明重新安装同一指定版本；不在当前任务内联网
解析、切换版本或改用仓库源码。

DxC 的调用由本 Skill 给出。每次只直接执行当前 Skill 明确写出的一个 DxC 命令，不寻找或猜测替代命令。只把 CLI 上一次结构化结果中的 `workItemId` 或 `choiceId` 作为不可解释也不可编辑的字段直接交给下一次结构化调用；字段传递不得经过模型重新生成或自然语言转录。禁止手工复制、拼接、改写、截取、解码、重建、落盘、持久化或转存这些值，也不要求用户接触它们。

调用仍在运行时，`DXC_BROWSER_EVENT` 只表示需要立即承载当前页面，不表示命令失败或完成。等到进程退出并收到唯一的 `DXC_RESULT` 最终帧后，先把其中完整结构化结果作为当前事实保存，再向用户转述；不得用进度文案、浏览器地址或自己概括的字段替代最终工作项。

禁止用 Python、Shell、PowerShell 临时脚本、循环、管道、命令替换、后台任务、并发或定时器包装 DxC 命令。禁止调用 CLI help，禁止查看源码、日志、内部文件或解析返回值内部结构来推断下一步。没有明确的下一步时，停在这里，如实告诉用户当前还不能继续。

CLI 失败时，若当前 Skill 明确规定了 CLI 返回选项、用户选择后继续的分支，只按该分支等待并提交用户选择。
其余失败禁止再次调用、轮询、跳阶段、重新进入阶段或创建替代项目。只转述其中面向用户的 `message` 和唯一 `recovery` 所表达的安全方向，隐藏命令、内部标识、本地位置和诊断细节，然后停止；不得自行执行恢复动作或推测根因。

若宿主无法把完整结构化字段直接传给下一次调用，停止并说明交接能力不足；不得为了继续而手抄或重建引用。
状态目录权限被拒绝时，用户的自然语言同意不改变沙箱。只有宿主实际授予目标目录权限后才能继续；
不要反复在相同受限环境执行，也不要修改全局安全配置、放宽目录权限或搬迁文章。doctor 的工作目录检查不代表文章状态目录可写。

面向用户只展示视觉方案、真实图片和确实需要回答的问题，不展示命令、内部标识、本地位置或实现过程。

接到当前工作项时，使用其随附的文章资料和视觉写作区；不要另行查找项目文件、画像、记忆、知识库、日志或源码。先完成封面和正文图各自要帮助读者理解什么的视觉方案，再执行一次 `dxc workflow advance --work-item <当前工作项> --json`。

工作项随附的创作记忆中，`enforce` 是必须遵守的约束，`guide` 是视觉指导，`suggest` 只作候选且不得自动逐字或机械套用；保留 `principle`、`judgment`、`expression` 等真实类型含义。

执行前完整阅读[视觉计划方法](references/visual-methods.md)。先判断视觉是否帮助理解，再选择真实素材的生产方式。视觉方案必须服务文章内容；不要用占位图、套模板图或与正文无关的图片推进。
完整流程随附 Research 时，用它逐阶段核对生命周期、矩阵和跨材料比较图；显式从视觉阶段开始且
Research 缺失时，不得声称完成了来源覆盖验证，涉及合并来源的图必须停下补材料或缩小为正文可证范围。

用户在本阶段明确修改、拒绝或反馈了可迁移到未来文章的视觉偏好时，另执行一次 `dxc memory signals record --automatic --project <随工作项收到的 projectId> --action <user-edit|user-feedback|user-rejection|user-choice> --summary <只描述用户行为的最小摘要> --json`。普通确认、单张图片细节和 Agent 自己的方案不记录；返回 `recorded: false` 时不提示、不重试。该独立动作不推进阶段。

CLI 要求补齐图片时，只处理它本轮分配的封面或正文图，并服从返回的比例、1:1 裁切模式、推荐尺寸与固定模式安全区；自动模式不自行猜坐标，交给 CLI 从真实图片解析并回退中央。使用真实生成结果或用户明确选择的素材，不能覆盖未重新分配的图片。完成后只执行一次 `dxc workflow advance --work-item <当前工作项> --json`。不要自行改变图片归属或另建素材流程。
每张新素材必须直接写成工作项声明的 `outputMediaType`；不得先创建 SVG、HTML 或其他设计稿，再要求用户安装临时转换工具。宿主没有能力直接生成指定格式时，如实说明并停在本阶段。

CLI 要求展示视觉结果时，同时展示视觉方案和真实带图预览，等待用户决定：采用则执行一次 `dxc workflow advance --work-item <当前工作项> --confirm --json`；要修改则修改方案或图片后再执行一次不带确认的推进；不采用则停下。缺少真实图片或图片不合格时，如实说明并停在本阶段，不降级为无图交付或自行重试。

用户明确要求从视觉开始新建文章时，执行一次 `dxc workflow start --title <用户主题> --from visual-plan --json`；已有文章只在用户从项目总览中明确选定后，把项目总览结构化结果中的 `projectId` 原样传递给一次 `dxc workflow start --project <项目总览返回的 projectId> --from visual-plan --json`。不得从文章标题猜测或重建；上下文丢失时，重新读取项目总览并让用户选择。随后仍只使用返回的当前工作项。
