# 瀚與 专利费用与费减查询（patentg-hanyuu）

瀚與 提供的中国专利数据只读查询服务，覆盖 **费减备案 / 应缴费用 / 著录项目 / 说明书 PDF / 企业工商信息** 五类能力，共 7 个工具。

## 前置条件

- 已连接本连接器并填写有效 **orkey**。orkey 由 `mcp.json` 的 `X-MCP-Orkey` 请求头自动注入，**AI 不需要、也不应该向用户索要或代为传递 orkey**。
- 凭证失效时返回 `isError: true`，文本含「orkey「…」无效或未授权」。此时提示用户重新连接并填写正确 orkey，**不要重试**同一请求。
- 全部为只读查询，无写入、无删除，无需二次确认。

## 一、工具总览与选择规则

| 用户想要什么 | 用哪个工具 | 不要用 |
| --- | --- | --- |
| 这家公司**能不能**费减（只要结论） | `is_fee_reduction_valid` | ~~`query_fee_reduction`~~ |
| 费减**历年备案明细** | `query_fee_reduction` | ~~`is_fee_reduction_valid`~~ |
| 专利**还要交多少钱 / 什么时候到期** | `query_patent_fee` | — |
| 专利**是什么 / 谁申请的 / 何时公开** | `get_patent_info` | — |
| **下载**专利说明书全文 PDF | `download_patent_pdf` | — |
| 公司**工商详情**（法人 / 地址 / 邮编） | `query_company_info` | ~~`search_company`~~ |
| 只有公司简称，要素材查上面的能力 | `search_company`（**仅辅助解析**，不返回工商详情） | — |

> **最容易混的两组**：
> ① `search_company` 是**模糊检索**，只给「名称 + 统一社会信用代码」，专为费减查询解析主体；`query_company_info` 才是查**工商详情**。用户问「法人是谁 / 注册地址在哪」，直接用 `query_company_info`。
> ② `is_fee_reduction_valid` 只回答是/否；要明细走 `query_fee_reduction`。不要为回答一个是/否的问题先调明细接口。

## 二、费减备案类

### 1. `search_company` —— 主体模糊检索（辅助工具）

| 参数 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `keyword` | string | 是 | — | 企业名称关键词，支持模糊匹配，不能为空 |
| `limit` | integer | 否 | 10 | 最多返回条数 |

```json
{ "keyword": "腾讯科技", "limit": 10 }
```

返回：

```text
关键词「腾讯科技」匹配到 10 家企业，请用 pick_index 指定序号（1 起）重新查询，或直接提供 gsid：

  [1] 济南腾讯科技有限公司  (gsid: 913701027591892671)
  [2] 腾讯科技（深圳）有限公司  (gsid: 9144030071526726XG)
  ...
```

**能力边界**：只做名称检索，**不返回**法定代表人、企业类型、注册地址、邮编。这类问题必须改用 `query_company_info`。

### 2. `query_fee_reduction` —— 费减备案明细

| 参数 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `company_name` | string | 是 | — | 企业/单位/个人名称（可模糊） |
| `gsid` | string | 否 | — | 统一社会信用代码或身份证号；已知时直接传，最快 |
| `pick_index` | integer | 否 | — | 多候选时指定第几个（1 起） |
| `orkey` | string | 否 | guest | **不要传**。凭证由请求头注入 |

```json
{ "company_name": "腾讯科技（深圳）有限公司", "gsid": "9144030071526726XG" }
```

返回（人类可读摘要 + 末尾可解析 JSON）：

```text
单位：腾讯科技（深圳）有限公司
统一社会信用代码：9144030071526726XG
数据来源：CNIPA 实时
费减备案记录：0 条
结论：未查询到费减备案记录

年度备案明细（按年度倒序）：
  （无）

{"company_name": "...", "gsid": "...", "current_year": 2026, "current_year_valid": false, "record_count": 0, "records": []}
```

取数优先使用末尾 JSON 行的 `current_year_valid` / `record_count` / `records`，不要从自然语言摘要里截取。

### 3. `is_fee_reduction_valid` —— 费减资格判定

参数同 `query_fee_reduction`（同样**不要传** `orkey`）。返回：

```text
否。腾讯科技（深圳）有限公司（9144030071526726XG）未查询到费减备案记录。数据来源：CNIPA 实时
```

#### 主体解析规则（两个费减工具通用）

1. 传了 `gsid` → 直接查询，最快，推荐；
2. 只传 `company_name` → 自动在企业库解析；命中多家时返回候选清单，需用 `pick_index` 指定序号（1 起）或补传 `gsid` 重查；
3. 解析不到（事业单位、个人）→ 服务提示需补充「完整单位名称 + 信用代码」或「姓名 + 身份证号」，**请原样转达用户**，不要自行猜测；
4. **多候选不等于已定位**：候选存在同名歧义时应先向用户确认，不要默认取 `[1]`；只有用户已明确全称时才用 `pick_index`。

## 三、专利费用与文献类

### 4. `query_patent_fee` —— 应缴费用查询（支持批量）

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `patent_nos` | array\<string\> | 是 | 中国专利申请号列表。**单件也必须写成只含一项的数组** |

- 专利号格式：**13 位**（12 位数字 + 1 位校验位，校验位可为 `0-9` 或 `X`）。带 `CN` / `ZL` 前缀、点分写法（`CN202511639665.1`）都能识别。
- **建议一次不超过 50 件**（接口分页上限）。多件务必合并成一次调用，不要循环单件调用。
- 个别号不合法**不影响**其它号，会在结果里单独列出。

```json
{ "patent_nos": ["2025116396651", "2024104299406"] }
```

返回：

```text
【2025116396651】2 项应缴费：
  - 发明专利第2年年费 ｜ 金额 135.00 ｜ 期限 2026-12-11
  - 发明专利第3年年费 ｜ 金额 135.00 ｜ 期限 2027-12-13

【2024104299406】2 项应缴费：
  - 发明专利第4年年费 ｜ 金额 180.00 ｜ 期限 2027-05-10

以下专利号不合法，已跳过：
  - BADNUMBER：不是有效的 13 位中国专利申请号（应为 12 位数字 + 1 位校验位，校验位可为 0-9 或 X）
```

**「无应缴费记录」是正常结果**（已缴清或不适用），不是错误，不要当作查询失败重试。

### 5. `get_patent_info` —— 著录项目信息

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `patent_no` | string | 是 | 13 位申请号（`2025116396651`）或 `CN` 开头的公开（公告）号（`CN121087679B` / `CN121087679A`） |

返回：发明名称、申请号、公开（公告）号、申请日、公开（公告）日、申请人、发明人、主分类号、摘要。

```text
发明名称：一种抗寒保暖的复合羊毛面料及其制作工艺
申请号：CN202511639665.1
公开（公告）号：CN121087679B
申请日：2025.11.11　公开（公告）日：2026.02.03
申请人：上海悠途实业有限公司　发明人：张凯;章晋增
主分类号：D04B1/10(2006.01)
摘要：本发明公开了……
```

首次查询可能耗时约 5 秒（服务端冷缓存），后续约 1 秒内，属正常现象。

### 6. `download_patent_pdf` —— 说明书全文 PDF

参数同 `get_patent_info`（`patent_no`）。返回：

```text
说明书 PDF 已就绪：
  文件名：CN121087679B.pdf
  下载地址：https://www.patentg.com/mcp/file/CN121087679B.pdf?t=eyJmIjoi…
（链接 10 分钟内有效，可直接在浏览器打开或另存为；过期后重新调用本工具即可获取新链接）
```

**返回值里的地址是「短时效签名取件链接」**：

- **有效期默认 10 分钟**，过期后访问会返回 `403`。这不是故障 —— 重新调用本工具取一条新链接即可，**不要**把旧链接重复给用户，也不要自行猜测或拼造链接；
- 链接与文件名**强绑定**，换文件名即失效；
- 链接很长且带签名参数，必须**整条原样**交付。

**必须遵守**：
- 返回的地址要**原样**交给用户，**不要改写、截断或加参数**；
- 文件已缓存在服务端，重复请求不会重复下载，**不要**为同一专利号反复调用；
- 只把地址给用户，**不要**自行下载、转存或解析 PDF 内容；
- 用户只要著录信息时用 `get_patent_info`，不要用本工具（会触发 5 秒级下载）；
- 若本工具的返回值提示「下载令牌签发失败」，说明本次调用的连接器凭证无效或缺失 —— 应提示用户重新连接连接器并填写正确的 orkey，不要重试。

> **给使用方（非 AI）的补充**：本工具的下载链接只能由**携带有效 orkey 的调用**签发。如果需要在自己的前端/后台生成「用户可直接点开」的链接，可调用 `POST /mcp/mcpdlissue`（同样必须带 `X-MCP-Orkey`，表单或 JSON 传 `filename`），返回 `{code:0, data:{filename, url, expires_in}}`。

## 四、企业工商信息

### 7. `query_company_info` —— 单个企业工商信息

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `keyword` | string | 是 | 企业**完整名称**（建议含「有限公司」等后缀，**至少 4 个汉字**）或统一社会信用代码 |

比信用代码更快更准，优先用全称。返回：

```text
腾讯科技（深圳）有限公司
●9144030071526726XG　●法人：马化腾　●2000-02-24
●深圳市南山区高新区科技中一路腾讯大厦35号　邮编：518000
广东省　深圳市
```

**能力边界**：不含经营范围、注册资本、股东、对外投资等，**不要**回答超出以上字段的内容。

## 五、推荐调用顺序

```text
费减场景
  只有简称 → search_company 取标准名称 + gsid → query_fee_reduction / is_fee_reduction_valid
  已知全称 → 直接 query_fee_reduction(company_name)
  已知 gsid → 一步到位
工商场景
  完整名称 / 信用代码 → 直接 query_company_info（不要先 search_company）
专利场景
  查著录 → get_patent_info
  查费用 → query_patent_fee（多件合并成一次数组调用）
  要全文 → download_patent_pdf，把地址原样给用户
```

## 六、错误场景与应对

| 现象 | 原因 | 应对 |
| --- | --- | --- |
| `isError: true`，含「orkey「…」无效或未授权」 | 凭证未配置或失效 | 提示用户重新连接连接器；不要重试 |
| `isError: true`，「下载令牌签发失败：本工具必须携带有效的 X-MCP-Orkey…」 | `download_patent_pdf` 在无有效凭证时被调用 | 提示用户重新连接连接器并填写 orkey；不要重试 |
| 用户反馈下载链接打开是 `403 凭证无效或已过期` | 签名链接已过 10 分钟有效期 | **重新调用 `download_patent_pdf`** 取一条新链接再给用户；不要沿用旧链接 |
| 用户反馈下载链接打开是 `401 缺少 X-MCP-Orkey 或下载令牌` | 链接被截断/改写过，签名参数丢失 | 重新调用工具取完整链接，整条原样交付 |
| `isError: true`，「错误：keyword 不能为空」 | 参数传空串 | 补全后重试 |
| `isError: true`，「企业名称太短：请提供至少 4 个汉字…」 | `query_company_info` 关键词过短 | 改用完整企业名称或统一社会信用代码 |
| `isError: true`，「错误：patent_nos 不能为空」 | 传了空数组 | 传入专利号数组，单件也要写成数组 |
| `isError: true`，「专利号全部不合法，未发起查询」 | 校验位不通过 | 按提示改用正确的 13 位申请号或 `CN` 公开号；校验位仅 `0-9` / `X` |
| 返回候选清单（多条） | 名称模糊命中多家 | 向用户确认主体，或用 `pick_index` / `gsid` 重查 |
| 提示需补充「单位名称+信用代码」或「姓名+身份证号」 | 主体不在企业库（事业单位、个人） | 原样转达，请用户补充后再查 |
| 「未检索到…对应的企业」（`isError: false`） | 工商库无该企业 | 属正常无结果，建议用户改用完整名称或信用代码 |
| 「无应缴费记录」/「未查询到费减备案记录」 | 未缴或未备案 | 属**正常结果**，直接按结论作答，不是错误 |

## 七、数据合规与使用边界

- 数据来源为 CNIPA 公开的专利数据及公开工商信息，查询结果**仅供参考**，正式结论以官方系统为准。
- **个人信息**：
  - `query_fee_reduction` 支持以**身份证号**查询个人费减备案——不要主动索取身份证号；用户提供后仅用于本次查询，回复中做掩码（如 `4403**********1234`）；
  - `query_company_info` 返回**法定代表人姓名**（自然人），不要在无关场景下复述或汇总该类信息。
- **不批量抓取**：不得为批量导出而循环调用；`query_patent_fee` 的批量能力仅用于用户明确要求的多件查询。
- 不存储、不转发、不把结果汇总写入外部系统或文件，除非用户明确要求且知晓。
- 能力边界：本服务只覆盖费减 / 费用 / 著录 / 说明书 PDF / 工商信息五类，不提供专利法律状态、审查文件、同族、引证、商标或软著数据，遇到此类需求应说明边界。
