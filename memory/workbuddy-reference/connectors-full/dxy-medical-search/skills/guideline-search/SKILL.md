# 指南查询

当用户需要查找临床诊疗指南、共识、规范或特定发布机构的指南时，使用 `search_guidelines`。典型问题包括：某疾病有哪些指南、某机构发布了何种指南、某主题的指南依据或指南原文入口。

## 连接与认证

使用已连接的“丁香园医学检索”MCP 连接器。首次使用由 WorkBuddy 引导用户在浏览器登录临床决策账号并授权。未连接或授权失效时，引导用户连接或重新授权；不要索取、输出或手工拼接 Token，不通过 shell 或 HTTP 请求替代 MCP 工具。

## 调用规则

1. 根据用户明确的检索意图使用本工具，无需选择场景胶囊。
2. 使用用户原始的自然语言问题作为 `query`，保留明确的疾病、临床问题、发布机构、地区和时间要求。
3. 用户只给出宽泛疾病名称时可直接查询。若用户要求定位具体推荐条款而问题未提供足够主题或人群条件，应先追问。
4. 一次用户请求只调用一次本工具。不要因希望扩大结果范围、想确认版本或结果为空而自行二次调用。

## 调用示例

调用 `search_guidelines`，参数如下（仅为检索请求，不代表真实结果）：

```json
{
  "query": "查找中国成人社区获得性肺炎诊疗指南"
}
```

`query` 为必填字符串，无默认值；结果是列表，没有总数或分页字段。

## 结果处理

- 输入仅含必填字符串 `query`，不能为空白；不要添加分页、数量、筛选或客户端 IP 参数。
- 成功结果位于 MCP `content` 的 text 中，内容是 JSON 数组；先检查 `isError`，错误文本不能当作结果解析。
- Tool 返回的是经 NLP 分析后调用指南检索得到的候选；当前接口没有固定 Top20 数量保证，不应将任一结果表述为唯一适用、现行有效或最新版，除非返回字段明确提供该信息。
- 默认按 MCP 返回顺序展示前 5 条，用户要求时可展示更多候选。保留 MCP 返回顺序。
- 每条结果展示：`documentTitle`、`sourceAuthority`、`publishDate`、`abstractText`、`url`；字段为空时省略，不补全。
- `sourceType` 固定为 `clinicalGuideline`。`abstractText` 只展示上游返回的摘要；为空则省略，不从标题、模型知识或其他内容补写摘要、推荐条款。
- `publishDate` 可能是原始日期文本，也可能是数字时间戳字符串；保留原值，不猜测单位或时区。`url` 为空时省略链接。

## 输出格式

```markdown
### 指南结果

1. **{documentTitle}**
   - 发布机构：{sourceAuthority}
   - 发布日期：{publishDate}
   - 摘要：{abstractText}
   - [查看来源]({url})
```

结果后可提示用户：如需判断指南的适用人群、推荐强度或完整条款，请查看原始来源并结合实际临床情境判断。

## 边界与异常

- 不要将指南检索结果转化为诊断、处方或治疗方案。
- 无结果时，建议补充疾病全称、临床问题、发布机构、地区或年份。
- 授权、额度、超时或服务错误时只反馈错误状态；不得重试、不得虚构指南、不得自动调用文献或药品 Tool。

## 错误恢复

- 未连接、登录或授权失效：引导用户通过 WorkBuddy 重新连接；令牌刷新由客户端处理，不自行刷新或循环重试。
- `query 不能为空`：补齐非空检索需求，由用户确认后发起新的查询。
- 工具执行失败或超时：说明本次查询失败，用户明确要求再试时再发起一次查询。错误信息不可当作检索结果。
- 不请求其他工具补齐结果。
