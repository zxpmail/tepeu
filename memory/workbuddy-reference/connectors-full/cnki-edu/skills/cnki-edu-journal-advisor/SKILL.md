# cnki-edu-journal-advisor（中小学教师教研论文投稿选刊版 WorkBuddy 版）

> **⚠️ 前置依赖（MCP server 注册）**
> 本技能仅依赖 **`edu`（公共知网 edu 网关，已注册、可用）**：文献检索，步骤 3 走 `mcp__<SERVER>__searchVectorBJ`。该工具直接返回每条文献的 `JournalName`(刊名)、`PinyinName`(拼音刊号)、`Author`、`PubDate`、`CitedTimes`、`DownloadedTimes`、`coreJournals`(核心/收录信号)、`CSSCI`、`url`(知网阅读链接) 等完整元数据——**无需从文件名反推刊名**。这是本技能唯一的数据源，无需任何额外配置即可正常工作。
>
> **文件解析说明**：WorkBuddy 的 Read 工具已内置 PDF/DOCX 文本抽取，步骤 1 直接用 Read 读上传文件即可，无需脚本转换。

## 🔐 前置权限校验（最高优先级，必须最先执行）

本技能的全部真实数据（期刊文献元数据）均来自「知网 edu（基教 / 研学）」MCP，需账号拥有「知网基教」权益才能调用。在调用**任何** edu MCP 数据工具（如 `mcp__<SERVER>__searchVectorBJ`）**之前**，必须先做权限校验：

1. 调用 `mcp__<SERVER>__userState` 工具（edu MCP 提供的权益校验接口，**无参数**）。
   - 工具名写法：`mcp__<SERVER>__userState`（`<SERVER>` 取自连接器「显示名」，会随重命名变化；若查不到，用 `ToolSearch(tool_names:["userState"])` 反查真实名称后再调用）。
2. **返回 `true`** → 账号有基教权益，正常进入流程。
3. **返回 `false`** → 账号**没有**基教权益：
   - **立即中止**，不再调用任何 edu MCP 数据工具；
   - 也不要用"检索无结果"去猜测原因——根因就是没权限；
   - 向用户输出下方固定提示，**不要**继续生成结果；
   - **⛔ 严禁绕过接口寻找替代方法**：不得改用大模型自身知识、公开网络资料、通用教研经验等非知网接口数据来"凑"出选刊 / 文献结果；没有权益即严格终止，由用户自行开通权益后重试。

> ⚠️ 无基教权益时的固定提示（原样输出、立即中止、严禁绕过接口）统一见 [_shared.md](references/_shared.md)「权限固定提示」，本 skill 不再重复誊写。

## 概述

面向**中小学教师**，帮助其把写好的教研论文（学科教学、作业设计、班级管理、德育、课题研究、课标落地等）投到**合适的「基础教育 / G4 教育类」期刊**。

区别于高校科研选刊工具，本版**不以影响因子 / CSSCI / SSCI 为核心指标**，而是围绕教师最关心的三件事做推荐与提示：

1. **投得对**——是不是基础教育 / 教育类刊物，主题是否契合；
2. **投得安全**——期刊是否正规、是否被三大网（知网 / 万方 / 维普）收录、会不会踩到假刊套刊；
3. **投得及**——版面费是否在合理区间、审稿出刊周期能否赶上评职称截止日期。

> **本技能不编造数据**：知网 `mcp__<SERVER>__searchVectorBJ` 只返回「刊名 + 主题相关发文频次 + 收录信号」，**不返回版面费、不返回省级/国家级定性结论、不返回审稿周期天数**。这些字段本技能一律标注「需自行核实」，绝不凭空填写。

## 工作流程

整体流程分为 4 个步骤，从用户输入到最终推荐展示，形成完整闭环：

```
步骤 1 → 步骤 2 → 步骤 3 → 步骤 4
输入      确认      检索      推荐
解析      解析      聚合      展示
                   (候选)   +核验清单
```

> **单一「主题启发式模式」**：本技能完全基于 `edu` 的 `mcp__<SERVER>__searchVectorBJ` 返回的真实文献元数据（刊名 + 主题相关发文频次 + 收录信号）做推荐，**不接入任何用户行为 / 轨迹画像**，不声称个性化分析。不存在"精准 / 启发式"双档位，所有推荐均为同一模式。

---

### 步骤 1：用户输入分析与内容解析

分析用户输入的内容或上传的文档，统一使用 **Prompt 1：论文核心信息提取提示词**（`references/prompts.md`）通过大模型提取论文标题、摘要、关键词。

**方式 ① — 用户上传论文文件：**

在 WorkBuddy 中直接用 **Read 工具** 读取用户上传的 PDF / DOC / DOCX 文件，提取文章全文文本（Read 已内置 PDF/DOCX 文本抽取，无需脚本转换）。

> **数据映射：** 将 Read 工具抽取出的全文作为 **Prompt 1**（`references/prompts.md`）中的 `{full_text}` 占位符传入。

**方式 ② — 用户直接输入文字内容：**

直接调用 **Prompt 1** 通过大模型从用户输入的文字中提取标题、摘要、关键词。

> **数据映射：** 将用户输入的文字内容作为 **Prompt 1**（`references/prompts.md`）中的 `{full_text}` 占位符传入。

**Prompt 1 提取字段：**

| 字段 | 类型 | 说明 | 去往步骤 |
|---|---|---|---|
| 标题 | string | 论文完整标题 | 步骤 2 确认 |
| 摘要 | string | 论文摘要全文 | 步骤 2 确认 |
| 关键词 | string[] | 4～6 个关键词 | 步骤 2 确认 |

---

### 步骤 2：解析结果确认（⛔ 确认节点）

> ⛔⛔⛔ **最高优先级流程控制 — 绝对不可跳过**
>
> 展示完下面的**解析结果确认卡片**后：
> 1. **立即停止输出** — 你的回复到此为止，不要有任何多余文字
> 2. **绝对禁止**调用任何 MCP 工具
> 3. **绝对禁止**进入步骤 3 及之后的任何步骤
> 4. **唯一允许的动作**：等待用户在聊天框中输入回复
>
> 只有当用户回复 **1/确认/正确/没问题** 后，下一轮对话才能进入步骤 3。

将步骤 1 提取的标题、摘要、关键词展示给用户确认。

**展示卡片（本轮输出的全部内容，输出后即停止）：**

```
论文解析完成，请确认以下信息：

📝 **【标题】** {从论文中提取的完整标题}


📋 **【摘要】** {摘要}


🔑 **【关键词】** {关键词1}、{关键词2}、{关键词3}、{关键词4}、{关键词5}


---

信息无误请确认，如有偏差可手动修改。

请回复：
- 输入 **1** 或"确认" → 开始推荐
- 输入 **2** 或"修改" → 手动修改信息
```

**用户回应处理（仅在用户回复后触发）：**

| 用户回应 | 处理方式 |
|---|---|
| 回复 **1** / "确认" / "正确" / "没问题" | → 进入步骤 3 |
| 回复 **2** / "修改" / 指出某字段有误 | 引导用户逐字段修正（标题/摘要/关键词），更新后再次展示确认卡片 |
| 用户直接输入修正内容（如"关键词改成 A、B、C"） | 解析修正内容，更新对应字段，重新展示确认卡片 |

---

### 步骤 3：相似文献检索与候选聚合（知网 edu 网关，主路径）

调用 `mcp__<SERVER>__searchVectorBJ` 工具（公共知网 edu MCP，server 名 `edu`，已在 WorkBuddy 注册）按文本向量检索相关文献，作为每条推荐期刊的"内容相关文献"来源，**并直接聚合出候选期刊**。

**调用参数：**

```json
{
  "text": "{步骤1提取的论文标题 + 关键词，以逗号或空格拼接}",
  "query_type": 3,
  "type": "0",
  "maxRecallNumber": 5
}
```

**参数说明：**
| 参数 | 必填 | 说明 |
|---|---|---|
| text | 是 | 检索文本，建议用论文标题 + 关键词拼接，体现主题 |
| query_type | 否 | 0 篇名 / 1 摘要 / 2 小标题 / 3 主题，默认 0；推荐用 3（主题）召回相关文献 |
| type | 否 | 文献类型：0 期刊 / 1 硕士 / 2 博士 / 3 会议 / 4 报纸，多值逗号隔开，默认 0（期刊） |
| maxRecallNumber | 否 | 最大返回条数，默认 20；此处取 5 |

> 注：`mcp__<SERVER>__searchVectorBJ` 直接返回完整文献元数据：每条结果含 `JournalName`(刊名)、`PinyinName`(拼音刊号)、`Author`(作者)、`PubDate`(发表时间)、`DownloadedTimes`(下载)、`CitedTimes`(被引)、`coreJournals`(核心/收录信号)、`CSSCI`、`url`(知网阅读链接)。`readUrl` 直接用返回结果的 `url` 字段（无需自行拼接）。

#### 3.1 候选期刊的聚合方法（直接用真实返回字段，不反推文件名）

`mcp__<SERVER>__searchVectorBJ` **直接返回**每条文献的 `JournalName`(刊名) 与 `PinyinName`(拼音刊号)，无需从 `文件名` 反推。候选期刊的算法如下：

1. 对步骤 3 返回的每条文献，取 `JournalName` 作为候选刊名；用 `PinyinName` 拼期刊导航链接 `navUrl = https://navi.cnki.net/knavi/journals/{PinyinName}/detail`（**仅内部拼接，不展示给用户**）。
2. 按 `JournalName` 聚合，统计出现频次（即"该刊发表了多少篇相关主题文献"），频次越高越值得作为候选。
3. 极少数 `JournalName` 缺失时，回退用 `文件名` 前 4 位作兜底展示（仅兜底，不依赖）。

> 这是"同类主题都发在哪些刊"的启发式信号，**非精确匹配**，且**不保证该刊为正规基础教育刊**——必须在步骤 4.2 的「📋 投稿前核验清单」中逐刊核验正规性。

---

### 步骤 4：推荐结果展示与反馈闭环

#### 4.1 推荐理由生成（Prompt 2）

对每条候选期刊，调用 **Prompt 2：推荐理由生成提示词**（`references/prompts.md`），输入候选聚合信息（主题相关发文频次 + 期刊客观字段） + 相似文献数据，生成面向教师的推荐理由，并**固定附带期刊资质核验提醒**（见 4.2）。不依赖任何用户轨迹数据。

#### 4.2 推荐结果展示

> ⚠️ **核心展示规则 — 面向教师、聚焦基础教育刊**

**展示模板（每条候选期刊按以下格式独立渲染）：**

```
## 🇨🇳 推荐投稿期刊（基础教育 / 教育类）

{若候选为空，显示 "> 📭 暂未匹配到相关教育类期刊，可尝试更换关键词或放宽主题"}

{遍历候选期刊数组，每条渲染如下卡片}

### {分级图标} {分级名称}：《{中文刊名}》

![期刊封面]({封面地址})

|------|------|

**📋 投稿前核验清单（每张卡片必附，固定提示）：**

> ⚠️ 以下项目本技能**无法自动获取**，请投稿前务必自行核实，规避假刊套刊：
> 1. **正规性**：登录「国家新闻出版署 → 期刊/期刊社查询」核对 CN 号与刊名是否一致；确认是纸质期刊而非仅电子刊/国际刊号。
> 2. **三大网收录**：确认期刊在**知网 / 万方 / 维普**之一可检索到正文（评职称通常要求上"三大网"之一）；仅 `mcp__<SERVER>__searchVectorBJ` 能证明知网可检索，万方/维普请另行核验。
> 3. **警惕假刊/套刊**：克隆刊（同名不同 CN 号）、套刊（用正刊 CN 号另立分册收钱）、只收钱不审稿的"水刊"均高度可疑；凡要求先交高额版面费才给录用且不在三大网收录的，切勿投递。
> 4. **版面费**：本技能无真实版面费数据，请以**期刊官网公示**及学校财务认可标准为准；明显偏低（如 ≤300 元/版）或偏高（如 ≥2000 元/版）均需警惕。
> 5. **出刊周期**：结合出版周期与"网络首发"判断；评职称有截止日期的，预留至少 6–12 个月。
```

**分级标准（教师版，以"主题契合度"为主）：**

| 等级 | 图标 | 契合度区间 | 适配评分 | 含义 |
|---|---|---|---|---|

| 备选 | 🥈 | 70% - 84% | 7.0~8.4 | 较为契合，可作备选 |
| 潜力 | 🥉 | 55% - 69% | 5.5~6.9 | 有一定关联，值得关注 |
| 关注 | 💡 | 40% - 54% | 4.0~5.4 | 契合度一般，建议横向比较 |
| 不推荐 | 📉 | < 40% | < 4.0 | 契合度低，建议慎重考虑 |

> **适配评分** = `契合度 ÷ 10`（保留 1 位小数）。

- 主题契合：该刊相关主题发文 X 篇，方向一致
- 教师适配：是否 G4 教育类 / 级别 / 出版周期是否利于快速出刊
- ⚠️ 注意：**投稿前务必按核验清单确认期刊正规性与三大网收录**（固定输出，不依赖数据推导）

|------|------|------|----------|------|------|------|

> 说明：`mcp__<SERVER>__searchVectorBJ` 直接返回 `篇名`/`JournalName`/`Author`/`PubDate`/`相关度` 等元数据，`readUrl` 取返回结果的 `url` 字段。本表是「延伸阅读」，不出"该投哪本刊"的结论；期刊名称与契合度由候选聚合提供。

**展示要求汇总：**

- **刊名展示规范（最高优先级）**：所有面向用户的刊名一律使用 `JournalName`(中文刊名)；**严禁输出 `PinyinName`(拼音刊号)、`文件名` 等内部代码作为可见文本**。导航/投稿链接的显示文字必须是刊名，拼音代码仅 agent 内部拼接 `navUrl`，绝不展示。
- **封面图片**使用 Markdown 语法 `![期刊封面]({封面地址})`，**禁止** `<img>` HTML 标签。若 `封面地址` 为空、null 或 undefined，直接跳过该行（不输出占位符、不留空行）。
- **链接行条件渲染**：有 `导航连接` → `🔗 [查看期刊详情]`；有 `官网地址` → `📮 [官方投稿]`；两者皆有（常见）→ 并排；仅官网 → 仅投稿；皆空 → 跳过。
- **不展示给教师的指标**：SSCI / ESCI / Scopus / WAJCI / CI指数 / WJCI分区 / 外文期刊推荐——已从教师版移除。
- **资质核验提醒**：每张推荐卡片**必须**附「📋 投稿前核验清单」固定提示，不得省略（核心安全闸）。
- **数据诚实**：版面费、省级/国家级定性、审稿周期天数、万方/维普收录——凡 `mcp__<SERVER>__searchVectorBJ` 未返回的一律标注"需核实/请自行核实"，严禁编造。

#### 4.3 反馈闭环

推荐结果展示完毕后，主动询问用户满意度：

```
💬 不满意？告诉我原因，重新调整

您可以回复：
- "满意" → 结束本次推荐
- "想要出刊更快的" → 按出版周期重新排序
- "要上知网的/省级的" → 按偏好重新筛选排序
- "这个期刊靠谱吗" → 展开该刊的核验要点与避坑提示
```

**用户反馈处理：**

| 用户反馈类型 | 示例 | 处理方式 |
|---|---|---|
| 指定偏好维度 | "想要出刊更快的" | 重新排序推荐列表，优先展示出版周期短的 |
| 指定偏好维度 | "要省级、便宜点" | 重新排序，优先展示省级 / 版面费友好（标注需核实） |
| 核验咨询 | "这个期刊靠谱吗" | 输出该刊的「投稿前核验清单」逐项要点 + 假刊识别提示 |
| 满意 | "满意" / "好的" / "谢谢" | 结束，回复："祝投稿顺利 🎉 记得按核验清单确认正规性" |

### 2. 相似文献检索 / 候选聚合 mcp__<SERVER>__searchVectorBJ（知网 edu 网关，主路径）

```
mcp__<SERVER>__searchVectorBJ({ "text": "{论文标题 + 关键词}", "query_type": 3, "type": "0", "maxRecallNumber": 5 })
```

> 公共 `edu` 网关的文献向量检索工具，返回**完整文献元数据**：每条结果含 `JournalName`(刊名)、`PinyinName`(拼音刊号)、`Author`(作者)、`PubDate`(发表时间)、`DownloadedTimes`(下载)、`CitedTimes`(被引)、`coreJournals`(核心/收录信号)、`CSSCI`、`url`(知网阅读链接)。`JournalName` 直接用于"候选期刊"按刊聚合，`PinyinName` 用于拼知网期刊导航页 `https://navi.cnki.net/knavi/journals/{PinyinName}/detail`，`url` 直接作为文献 `readUrl`（其中 `PinyinName`/`文件名` 仅内部拼链接/兜底，不展示给用户；`coreJournals`/`CSSCI` 仅作收录信号参考，不向用户展示为硬指标）。`CitedTimes`(被引)/`DownloadedTimes`(下载) 在「📑 内容相关文献」表中正常展示。

### MCP Server 注册（前置依赖）

本技能仅依赖「知网 edu」MCP 连接器（提供 `mcp__<SERVER>__searchVectorBJ` 文献检索与候选聚合）：

> 连接器由用户在本机 WorkBuddy 中自行添加并连接，**具体网关端点不在本技能内硬编码**。连接后工具名为 `mcp__<SERVER>__searchVectorBJ`，前缀随显示名变化，运行时以 `ToolSearch` 实际可用工具为准。

> ⚠️ 本技能**不依赖**任何用户行为 / 轨迹画像服务，也不依赖其他分析类端点。所有推荐均基于 `mcp__<SERVER>__searchVectorBJ` 真实返回的文献元数据。

## 注意事项

1. **上传论文直接用 Read 工具读取**：WorkBuddy 的 Read 工具已内置 PDF/DOCX 文本抽取，无需脚本；仅当需更强版面解析时改用 `layoutFullProcess`。
2. **单一主题启发式模式**：本技能完全基于 `edu` 的 `mcp__<SERVER>__searchVectorBJ` 返回的真实文献元数据做推荐，**不接入任何用户行为 / 轨迹画像**，不声称个性化分析。不存在"精准 / 启发式"双档位。
3. **业务数据需二次解析**：MCP 返回的 `result.content[0].text` 为 JSON 字符串，需 `JSON.parse` 获取业务数据。
4. **推荐理由必须基于真实数据**：不得编造期刊数据。
5. **数据不足时坦诚说明**：若候选聚合结果偏少，明确提示"可尝试更换关键词或放宽主题"。
6. **语气风格**：保持教研顾问式的专业亲切语气，不使用营销话术；不替期刊打包票"一定能发"。
7. **地区表述规范**：涉及学术期刊地域信息时，香港、台湾、澳门须明确标注"中国香港""中国台湾""中国澳门"。
8. **隐私保护**：推荐计算不依赖任何个人行为数据，无用户轨迹可泄露。
9. **反馈闭环**：每次推荐后主动询问满意度，保持对话开放，支持用户随时调整。
10. **⛔⛔⛔ 确认节点必须暂停（最高优先级）**：步骤 2（解析确认）是**用户确认节点**。展示内容后必须立即停止、等待用户回复。严禁在用户回复前自动执行后续步骤或 MCP 调用。
11. **MCP 调用范式（WorkBuddy）**：文献检索调用为 `mcp__<SERVER>__searchVectorBJ({text,query_type,type,maxRecallNumber})` 原生调用（唯一主路径）。
