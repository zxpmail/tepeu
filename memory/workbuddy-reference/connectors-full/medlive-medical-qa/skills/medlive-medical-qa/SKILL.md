# 医脉通医学问答

通过医脉通医学问答服务回答医学问题。答案由检索增强生成，适合临床用药、适应症、指南推荐、诊疗方案等场景。
提问（`medlive_ask`）会消耗用户配额，其余工具只读、不消耗。

## 认证

本连接器使用 OAuth 授权。用户首次连接时在浏览器登录医脉通账号并确认授权，**无需用户填写任何 Token**；凭证由 WorkBuddy 自动注入请求头。

- AI **不要**在对话里询问、拼接或输出任何 Token。
- 授权失效的两种表现：HTTP 401（`error: invalid_token`，缺 Bearer token）；或工具返回 `isError: true` 且文案为「授权已失效，请重新连接本连接器以完成授权」。此时提示用户重新连接本连接器即可，**不要**尝试自行绕过。

## 工作流

四个工具的分工与串联：

| 工具 | 用途 | 配额 |
| --- | --- | --- |
| `medlive_ask` | 提问 / 追问，获取答案 | 消耗 M星/提问次数 |
| `medlive_upload_file` | 上传附件供文档问答 | 不消耗 |
| `medlive_get_answer` | 按 `log_uuid` 兜底取回 / 回看单条答案 | 不消耗 |
| `medlive_list_history` | 会话历史分页回顾 | 不消耗 |

### 提问与追问

- 首次提问直接调 `medlive_ask`，**不要**传 `chat_group_uuid`（服务会自动新建会话）。
- **追问必须带上一轮返回的 `chat_group_uuid`**，否则会新建会话、丢失上下文。用户说"接着上面问""那老年人呢"等，属于追问。
- 返回正文末尾 `---` 之后的 `log_uuid`、`chat_group_uuid` 是追问与兜底必需，回答用户后记住它们；它们是程序元信息，**不要展示给用户**。
- 答案正文是已渲染好的 Markdown，**原样完整输出**，不要改写、删减、总结、翻译或补充。
- 服务端判定无需检索时（非医学问题、附件无文字、检索为空），话术照常返回但 `structuredContent.no_answer = true`：照话术如实回复，不要补造医学结论。

### 文档问答

用户带附件/文档提问时：先 `medlive_upload_file` 上传（返回 `file_uuid`），再把它放进 `medlive_ask` 的 `file_uuids`。解析未完成的文件**不要**拿去提问；同一份文件只上传一次。

### 回顾与兜底

- 回顾会话：先 `medlive_list_history` 分页定位，某条需要完整答案再 `medlive_get_answer` 取详情。
- `medlive_ask` 超时或流中断后：用同一 `log_uuid` 调 `medlive_get_answer` 兜底取回，不要重复提问。
- 这两个工具只读、不消耗配额，也不会新建会话。

## 调用规则（重要）

1. **`medlive_ask` 会真实消耗用户配额**：同一问题不要重复调用；能复用上一轮答案时不要重新提问。
2. **`medlive_ask` 是同步阻塞调用**，复杂问题可能 1~3 分钟：等待期间不要并发重复调用同一个问题。
3. **失败时原样输出**工具返回的可读错误文案（`isError: true`）——与答案正文一样，**不要改写、删减、翻译或补充**；可在此基础上给出下一步（如用 `medlive_get_answer` 复核、或提示重新连接）；**不要**凭记忆补出医学结论。
4. 答案含「答案在流中断后从数据库取回」标注时，说明答案是在流中断后从数据库取回的，内容完整可用；若工具返回「答案流中断且未能从数据库取回完整答案」，说明答案不完整，如实转述并可用 `medlive_get_answer` 复核该记录。

## 禁止事项

- 不要把本连接器当作通用搜索引擎或非医学问题助手使用。
- 不要代替医生给出确诊结论；回答需保留来源依据，并提示以临床判断为准。
- 不要在未获得用户明确意图时批量、循环调用 `medlive_ask`（会持续消耗配额）。
