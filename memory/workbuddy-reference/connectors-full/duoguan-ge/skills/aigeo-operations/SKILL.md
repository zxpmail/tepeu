# AIGEO GEO 运营

## 一、诊断类请求：先取规范，再生成

判断依据是**用户的口语说法**，用户不会说工具名。出现下列任一说法即命中：

- 「帮我生成一个 XXX 的 GEO 诊断报告」
- 「帮我生成 XXX 的 GEO 诊断报告和整改方案」
- 「XXX 在 AI 里的表现怎么样 / AI 可见性如何」
- 「分析下 XXX 在豆包、DeepSeek、通义千问里的曝光和推荐情况」
- 「XXX 的品牌 AI 搜索诊断」

**命中后的第一步：调用 `geo_brand_diagnosis_report`**，取回服务端当前维护的交付规范，然后严格按其中的章节结构、执行顺序、逐章取数口径与合规红线生成。

- **不要凭记忆或历史版本动笔。** 规范由服务端维护、随时可能更新，**以工具返回的内容为唯一准绳**。
- **不要反问「是否需要生成报告」。** 收到即开始，先取规范再取数。
- 用户只给了品牌名就按品牌名做，**不要因为缺行业、城市等信息而追问**；查不到的字段由规范指引记为「需人工补充」。

> 规范正文不在本技能内，而是由 `geo_brand_diagnosis_report` 实时返回。同一份内容也通过 MCP Prompt `geo_brand_diagnosis` 对外提供（客户端可列举、用户可手动选用），两者始终同源。

## 二、合规底线（任何版本都不变）

- 严禁编造数据、虚构检索结果，或把推演写成平台官方实测；
- 禁止「保证上榜」「稳进前三」「稳居第一」等效果承诺；
- 正文不得出现电话、微信号、网址等联系方式；
- 基于公开语料的提及率、推荐率、排名推演，必须标注「⚠️ 虚拟推演，非平台官方数据」；
- 查不到的数据写「需人工补充」，不得用常识或行业均值替代。

完整红线与交付前自查清单以 `geo_brand_diagnosis_report` 返回的规范为准。

## 三、能力发现顺序

连接器的 Tools 与 Prompts 是两类独立能力，列举其一不会带出另一类：

1. `tools/list` → 获取当前可用 Tool 清单（诊断规范、GEO 数据、内容、关键词、发布等）；
2. 诊断类请求 → 先调 `geo_brand_diagnosis_report` 取最新规范；
3. 取数 → 优先用只读 Tool，按其入参 Schema 传参；
4. 需要确认某个 Tool 的用途与参数时查 `references/tools-reference.md`。

## 四、其他能力与使用原则

能力域：GEO 总览与分析、文章与内容管理、内容创作与素材处理、发布任务与记录、网站与页面、关键词查询与管理、租户资料与算力信息。

- 先按用户意图选最匹配的 Tool，再按其入参 Schema 传参；
- 有副作用的操作（新增、修改、删除、启停、发布、上传）执行前必须说明目标与影响并取得确认；
- 删除类动作必须显式传 `confirm: true`，否则服务端拒绝；
- 异步动作成功仅代表任务已提交，需再用查询 Tool 轮询结果；
- 查询类请求优先只读 Tool，分页遵循 `pageNo` / `pageSize` 上限；
- 不展示或索要服务端内部 Token，不在回复中输出完整凭证；
- 上游返回业务错误时直接说明失败原因，并保留 request ID（如有）；
- 不要猜测租户、任务、文章、关键词或批次的唯一标识。
