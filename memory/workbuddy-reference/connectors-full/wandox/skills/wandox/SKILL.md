# 麦多AI Skill

通过麦多AI平台查询与操作跨境电商全链路业务数据。

## 触发场景

**使用本连接器**：用户询问跨境电商经营数据，或需要操作业务单据时 —— 销售 / 订单 / 库存 / Listing / 广告 / 退货 / 评论 / 利润 / 结算、仓储 / 采购 / 调拨 / 头程、Wayfair 平台、1688 采购、选品打标、目标效能。

**不要使用**：与跨境电商业务无关的通用任务（写文档、做 PPT、本地文件处理），WorkBuddy 自身能力更强。

## 如何找到需要的工具

本连接器暴露 **440+ 个业务工具**（覆盖 14 个业务技能族），数量随 Token 授权范围增长（开通租户私有连接器后更多）。WorkBuddy 会以「延迟加载」方式处理：**工具定义不会全部常驻上下文**，需先按关键词检索加载，再调用。

执行方式：

1. 按导航表或 Recipe 的**检索关键词**查找工具，命中后加载其参数定义
2. 依据加载到的参数定义构造入参并调用
3. 首次检索无结果时，换同义词重试；仍无结果再换业务族

检索技巧：

- 用**业务名词**而非口语。搜「FBA库存」，不要搜「货快没了」
- 工具名是英文技术路径（如 `skill_AMAZON_OPERATE__erp__fba-inventory__listing-fba-list`），但描述为中文，**中文关键词可以命中**
- 一次可并行检索多个候选词，提高命中率
- 取不到数据时，可先查 `whoami` 确认当前 Token 绑定的是哪个账号与业务域

> 本文件按**业务域**组织，不逐条枚举工具名 —— 工具清单随服务端持续迭代（当前 440+ 个，且随 Token 授权范围变化），逐条枚举既会过时也会淹没业务语义。具体工具请通过检索获取。

## 授权方式

身份**完全由连接器配置里的麦多AI Token 决定**，连接器自身不做登录、不做账号切换：

- 用户在**连接器配置页**填入麦多AI Token，平台自动以请求头 `Authorization: Bearer <Token>` 注入每次调用
- 可访问的店铺、平台、业务域与数据范围，全部由该 Token 绑定
- 提示用户填写的位置：WorkBuddy → 连接器管理 → 麦多AI → 配置

排查取不到数据时按报错分流，**不要反复重试同一次调用**：

| 返回 | 含义 | 处置 |
|---|---|---|
| 「未登录」/「未授权」 | Token 缺失、已失效，或未随请求发出 | 告知用户到连接器配置页**检查并更新 Token** |
| 「MCP 套餐已过期」 | Token 有效，但账号套餐到期 | 告知用户前往 `https://store.wandox.com/#pricing` **续费**，重试无用 |
| 查得到数据但范围不对 | Token 绑定的账号 / 业务域不符 | 提示用户确认填入的是目标账号的 Token |

需要确认当前连的是哪个账号时，调 `whoami`（只读，返回 user_id / 用户名 / domain）。

### 一、销售与经营

#### R01 · 店铺销售健康诊断

- **触发**：销售异常 / 今天卖得怎么样 / 为什么销量掉了 / 店铺健康度
- **检索**：`店铺销售` `实时销量` `店铺表现` `销售分析`
- **步骤**：
  1. 取当日与昨日、上周同日对比，定位日环比与同比异常
  2. 下钻子 ASIN 维度，找出拖累 TOP3
- **输出**：健康结论 + 拖累 ASIN 清单 + 改进建议

#### R02 · 销量异动排查（暴跌 / 暴涨）

- **触发**：哪些产品掉量了 / 什么产品在起量 / 销量暴跌 / 销量暴涨
- **检索**：`销量暴跌` `销量暴涨` `销量趋势` `实时销量ASIN`
- **步骤**：
  1. 暴跌：筛近 7 天或 14 天环比跌幅超 30% 的 ASIN
  2. 暴涨：筛环比涨幅超 20% 的 ASIN
  3. 对重点 ASIN 追查原因，转 R05（Listing 掉单）、R08（广告）、R14（库存）
- **输出**：异动名单（ASIN + 变化幅度 + 初步归因）

#### R03 · 本周销售复盘

- **触发**：本周卖得怎么样 / 本周 TOP / 周报数据 / 销售额排名
- **检索**：`本周销售` `销售榜` `销售额前10` `父ASIN` `子ASIN`
- **步骤**：
  1. 拉本周销售额趋势与订单状态分布
  2. 输出父 ASIN、子 ASIN 销售额 TOP10 榜单
- **输出**：周度复盘摘要 + 榜单

### 二、Listing 优化

#### R04 · Listing 质量分析

- **触发**：Listing 有什么问题 / 怎么优化 Listing / 合规检查 / Listing 评分
- **检索**：`Listing质量` `Listing表现` `Listing列表`
- **步骤**：
  1. 按质量模型逐模块评分（标题、五点、图片、属性变体等）
  2. 检查合规项
  3. 列出低分模块
- **输出**：评分明细 + 分模块优化方向

#### R05 · Listing 掉单排查

- **触发**：突然掉单 / 订单突然少了 / Listing 出问题
- **检索**：`Listing掉单` `Listing变动记录` `Listing事件` `Listing变更日志`
- **前置**：部分数据需先执行「运营天眼」
- **步骤**：
  1. 查 Listing 变动记录（标题、图片、价格、BSR、评分、评论数）
  2. 锁定异常变化点与发生时间
  3. 给出对应 SOP
- **输出**：掉因定位 + 处置 SOP

#### R06 · Listing 图片与文案优化

- **触发**：图片要不要改 / 和竞品比差在哪 / 标题五点优化 / 关键词埋词
- **检索**：`图片诊断` `Listing文案` `标题` `五点` `关键词埋词` `竞品`
- **步骤**：
  1. 主副图 100 分制评分，指出拖后腿的图
  2. 对比我方与 3 个竞品 ASIN 的文案差异
  3. 按目标关键词重写标题与五点
- **输出**：图片评分 + 文案改法 + 优化后文案

#### R07 · AI / Alexa 推荐适配诊断

- **触发**：能不能被 AI 推荐 / Alexa 能不能读到 / AI 搜索能不能搜到
- **检索**：`Alexa` `AI检索` `推荐诊断`
- **步骤**：五维评分并给出优化文案
- **输出**：适配评分 + 文案建议

### 三、广告投放

#### R08 · 店铺广告健康诊断

- **触发**：广告钱花哪了 / 广告效果怎么样 / 广告浪费在哪

  1. 汇总全店与分店铺的 CTR / CVR / ACOS，附环比
  2. 列出高浪费活动位
- **输出**：广告效率评估 + 高浪费清单

#### R09 · 搜索词表现分析

- **触发**：哪些搜索词浪费钱 / 搜索词分析 / 该否定哪些词

- **步骤**：
  1. 按流量到效率四级漏斗对搜索词分层
  2. 各层级给对应行动建议
  3. 输出否定词清单
- **输出**：分层结论 + 否词建议

#### R10 · 关键词投放诊断

- **触发**：关键词烧钱 / 调价还是换匹配 / 关键词效果差
- **检索**：`关键词数据` `关键词竞价` `广告组关键词`
- **步骤**：分层判定竞价合理性，给出调价或调整匹配方式的建议
- **输出**：逐词调整建议

#### R11 · 止损筛查（高 ACOS / 零出单）

- **触发**：ACOS 太高 / 哪个活动该停 / 花了钱不出单
- **检索**：`广告活动` `自动投放` `商品投放` `关键词投放` `广告SKU`
- **步骤**：
  1. 筛高 ACOS 且花费达标的投放：自动 / 商品 / 关键词三类分别处理
  2. 筛零出单投放（0 单且点击 ≥ 50，或花费 ≥ $20 且 ACOS ≥ 50%）
  3. 生成暂停或降价待办
- **输出**：止损候选清单
- **注意**：**止损执行属于写操作，必须先向用户确认后再执行**

#### R12 · 新品广告启动

- **触发**：新品怎么开广告 / 新品启动 / 冷启动没思路
- **检索**：`新品` `广告活动` `品类基准`
- **步骤**：按官方基准给出冷启动动作清单
- **输出**：启动方案

#### R13 · 加词与放量

- **触发**：哪些词值得加投 / 怎么放量 / 加词建议
- **检索**：`搜索词` `关键词` `加词` `词库`
- **步骤**：
  1. 筛 ACOS < 40% 且 CVR > 12% 的高效词
  2. 给出加词与提价建议
- **输出**：加词清单与竞价范围

## 风险分级与执行要求

| 级别 | 判定 | 工具示例 | 执行要求 |
|---|---|---|---|
| 只读 | 路径末段是 get / list / query / page / detail / index / schema / summary / chart / total 等读取形态 | 绝大多数查询类（约 395 个） | 直接执行 |
| 写操作 | 路径末段含 create / update / save / modify / edit / add / delete / remove / send / cancel / audit / publish / submit / sync / renew / upsert / import / handle 等动作（约 50 个） | 创建采购单、调拨单、批量截单、订单审核、修改 Listing、发邮件、加否词、改竞价与预算、打标签、建待办 | **必须先向用户复述操作内容与影响范围，获得明确同意后执行** |

> 上表是**启发式分级**，仅供快速判断。**只要工具具备创建 / 修改 / 删除 / 发送 / 提交语义，一律按写操作处理**；拿不准时按写操作对待。

写操作补充规则：

- 批量类操作**单次不超过 30 条**，超出应先与用户拆分确认
- 涉及金额、价格、预算、竞价的修改，必须逐项列出变更前后数值
- 创建类单据执行后返回单号，并提示用户去对应系统复核

## 输出规范

- 默认中文输出；保留工具返回的关键字段原文
- 金额标注币种；**涨用红色、跌用绿色**（中国市场惯例）
- 长列表先给摘要（总量、Top N、异常项），再给明细
- 数据缺失时直说缺失原因，不要用推测填充

## 反例（Incorrect Flow）

- 不要自行拼接 HTTP 请求调用麦多AI接口，只通过工具调用
- 不要尝试登录、授权、切换账号类操作 —— 身份完全由连接器配置的 Token 决定
- 不要在未检索工具的情况下猜测工具名或参数
- 不要编造店铺、ASIN、SKU、订单号等标识符，必须来自工具返回或用户提供
- 不要在未获得用户确认时执行写操作
- 不要把「查询不到」解释为「数据为零」
