# 萌宠短剧

**这是什么**：**以猫、狗等动物为主角**的剧情短视频——宠物拟人（会说话、有人类的工作和生活：猫咪打工、
狗狗上班、宠物版霸总）、宠物视角的日常（主人上班后家里发生了什么）、宠物与主人之间的搞笑 / 温情故事、
萌宠反转小剧场。看点是**反差萌**：动物做人类的事、用人类的口吻吐槽，再加一个反转笑点或泪点。
主角是宠物，主人是配角；系列 = 同一只（同一群）宠物每集一个新故事。

**宠物主角的样子是这个系列的招牌**：品种、毛色、花纹、体型、标志性配饰一次定好、跨集不漂；
用户传了自家宠物的照片，就以照片为准。

**宠物该说话就说话**：这是 AI 视频，开口对白是常态，嘴在动、口型对得上；内心 OS（画外音念心里话）
只是一种可选的表现手法，剧情要反差时用，可以和开口说话在同一集里混着来。

**画面风格不由本品类规定**：真实质感、3D、卡通、手绘都可以，用户选什么就是什么。

**不属于本品类**：
- 给 0~9 岁孩子看的动物童话、动物儿歌 → 儿童视频（kids-video）；
- 以人类为主角、宠物只是道具或背景的剧情 → 短剧（short-drama）；
- 宠物用品、宠物食品的带货 → 电商带货（ecommerce-promo）；
- 漫画风的动物拟人连载，用户点名要「漫剧」→ 漫剧（anime-drama）。

## 各环节细则去哪看

**这张表是唯一的指引** —— 文件名由本品类自己定，读之前照这里对，不要凭约定猜。
需要哪个环节就读哪一份（都在本目录下）：

| 环节 | 文件 | 谁在什么时候读 | 里面有什么 |
| --- | --- | --- | --- |
| 访谈与落库参数 | `interview.md` | 访谈环节：建项目 / 建下一集，开口问之前 | 宠物主角、这一集的小故事、单集还是系列 |
| 编剧 | `script.md` | 剧本师：动笔之前 | 反差萌、故事骨架、宠物的「说话」怎么写、素材清单列什么 |
| 分镜 | `storyboard.md` | 分镜师：动笔之前 | 宠物视角的机位、反应与反转的节奏、宠物说话怎么拍 |
| 素材 | `asset.md` | 素材师：动手之前 | 宠物主角怎么写、照片为准、宠物的声音 |

⚠️ **通用的东西不在这里**：台词怎么写、人物怎么立、表演怎么写、字段清单与落库流程、
合规红线——那些对所有品类都一样，已在各角色的通用细则里。这几份只有**萌宠短剧特有的**部分。

## 落库字段这样填

- `story_mode`：**缺省 `anthology`**——每集一个独立的小故事，宠物主角跨集复用。
  只有用户明确要「连着讲、下一集接着上一集」才用 `serial`。
- `finale_style`：`anthology` **恒 `closed`**——每集的笑点或泪点在本集落地；`serial` 按通用规则问。
- `is_finale`：`anthology` **恒 `false`**；`serial` 按通用规则问。

⚠️ `story_mode` 用户没提就直接填 `anthology`，不问；`anthology` 时 `finale_style` 与 `is_finale` 不问；这几项复述里不出现。

## 进入各环节时带上品类名

剧本 / 素材 / 分镜每个环节**各自有技能清单**，给了品类名就能自己定位到本目录、
照上面那张表读自己那一份。所以交给各环节的任务描述里只写品类，例如：

> 本项目品类 pet-drama，动笔前先按技能清单读它的 SKILL.md 与编剧那一份细则。

⛔ **不要替它们写文件路径**——文件名是本品类自己的事（上面那张表随时可以改），
路径写进任务描述就等于把它钉死在 prompt 里。
