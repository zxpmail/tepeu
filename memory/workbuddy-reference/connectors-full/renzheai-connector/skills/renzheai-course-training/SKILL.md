# 课程培训

**这是什么**：**有明确学员、有学习目标**的教学视频——企业内训（新员工入职、规章制度、安全规范、服务话术）、
软件 / 设备操作教程、技能课程片段、知识付费课程里的一节。核心是**学员看完能做到或记住某件事**：
会按步骤操作、知道哪条红线不能碰、遇到这种客户该怎么说。

常见形态：一位固定的讲师出镜讲解 + 情景演示（正确做法 / 错误做法对比）+ 步骤分解 + 每节结尾小结要点。
系列 = 一门课的第 1 节、第 2 节……，讲师形象跨集复用。

**用户给了讲义 / 制度原文 / PPT / 文档时，以材料为准**：要点与步骤不许遗漏、不许改错顺序、专业术语不许改写。

**画面风格不由本品类规定**：实拍质感、商务写实、动画、扁平插画都可以，用户选什么就是什么。
本品类管的是「教会学员」这件事本身——目标、步骤、示范、复习。

**不属于本品类**：
- 面向大众、没有明确学员和学习目标的「为什么」类讲解 → 知识科普（`knowledge-explainer`）；
- 对外展示企业形象、给客户和合作方看的 → 企业宣传片（`corporate-promo`）；
- 给 0~9 岁孩子看的 → 儿童视频（`kids-video`）；
- 卖课的推广片、招生片 → 广告片（`commercial-ad`）/ 电商带货（`ecommerce-promo`）。

边界判据：**看完之后，学员是不是要去「做到」或「考到」某件事**？是 → 本品类。

## 各环节细则去哪看

**这张表是唯一的指引** —— 文件名由本品类自己定，读之前照这里对，不要凭约定猜。
需要哪个环节就读哪一份（都在本目录下）：

| 环节 | 文件 | 谁在什么时候读 | 里面有什么 |
| --- | --- | --- | --- |
| 访谈与落库参数 | `interview.md` | 访谈环节：建项目 / 建下一集，开口问之前 | 学员与学习目标、教学材料、一节还是一门课（serial / anthology 判据） |
| 编剧 | `script.md` | 剧本师：动笔之前 | 一节课的骨架、忠于材料、正误对比、步骤怎么讲、画面上的字、素材清单列什么 |
| 分镜 | `storyboard.md` | 分镜师：动笔之前 | 讲解与演示交替、步骤看得清、正误对比的构图 |
| 素材 | `asset.md` | 素材师：动手之前 | 讲师、演示场景与设备、小结卡与界面截图、音色怎么写 |

⚠️ **通用的东西不在这里**：台词怎么写、人物怎么立、表演怎么写、画面文字的通用判据、字段清单与落库流程、
合规红线——那些对所有品类都一样，已在各角色的通用细则里。这几份只有**课程培训特有的**部分。

## 落库字段这样填

- `story_mode`：一门课分几节、**各节有先后顺序**（下一节要用到上一节学过的东西）→ `serial`；
  各节**互相独立**（一条制度一节、一个技巧一节，先看哪节都行）→ `anthology`。判据与问法见 `interview.md`。
- `finale_style`：**恒 `closed`**——每一节都要收在小结上，不留悬念。不问、不复述。
- `is_finale`：`serial` 时 = 这门课的最后一节，按通用规则问；`anthology` **恒 `false`**。

## 进入各环节时带上品类名

剧本 / 素材 / 分镜每个环节**各自有技能清单**，给了品类名就能自己定位到本目录、
照上面那张表读自己那一份。所以交给各环节的任务描述里只写品类，例如：

> 本项目品类 course-training，动笔前先按技能清单读它的 SKILL.md 与编剧那一份细则。

⛔ **不要替它们写文件路径**——文件名是本品类自己的事（上面那张表随时可以改），
路径写进任务描述就等于把它钉死在 prompt 里。
