# 祝福视频

**这是什么**：**送给具体的人**的视频——生日、春节拜年、中秋 / 端午 / 元旦等节日问候、婚礼、结婚纪念日、
毕业、乔迁、开业、升职、公司年会、员工生日 / 司庆、给客户的节日问候。
它的成败只看一件事：**被祝福的人看完，觉得自己被记住、被在乎**。所以**具体比华丽重要**——
叫得出名字、说得出关系、提得到一段共同的回忆或对方的一个特点，比一万句「万事如意」都有分量。

常见形态：主角是**被祝福的人**（用户传照片）、**送祝福的人**、或者**一个可爱的形象 / 吉祥物**代为送祝福；
结尾一句祝福语点题。题材与调性跟着场合与用户走：喜庆、温馨、搞笑、庄重都可以。

**不属于本品类**：
- 企业对外的品牌节日营销片（节日借势、拿去投放的）→ 广告片（commercial-ad）；
- 年会上放的企业形象片、年度回顾片 → 企业宣传片（corporate-promo）；
- 有完整剧情冲突的故事（哪怕发生在过年、婚礼上）→ 短剧。

边界判据：**这条片子是送给一个（或一群）具体的人的吗**？是 → 本品类。

## 各环节细则去哪看

**这张表是唯一的指引** —— 文件名由本品类自己定，读之前照这里对，不要凭约定猜。
需要哪个环节就读哪一份（都在本目录下）：

| 环节 | 文件 | 谁在什么时候读 | 里面有什么 |
| --- | --- | --- | --- |
| 访谈与落库参数 | `interview.md` | 访谈环节：建项目 / 建下一集，开口问之前 | 送给谁、什么场合、谁送的、那一两件具体的事；照片与祝福语原文 |
| 编剧 | `script.md` | 剧本师：动笔之前 | 祝福的骨架、怎么写得具体、名字与祝福语一字不改、画面上的字、素材清单列什么 |
| 分镜 | `storyboard.md` | 分镜师：动笔之前 | 节奏跟着场合、被祝福的人要看得清、结尾祝福停得住 |
| 素材 | `asset.md` | 素材师：动手之前 | 照片里的人以图为准、场合的场景与道具、祝福字卡、音色怎么写 |

⚠️ **通用的东西不在这里**：台词怎么写、人物怎么立、画面文字的通用判据、字段清单与落库流程、
合规红线——那些对所有品类都一样，已在各角色的通用细则里。这几份只有**祝福视频特有的**部分。

## 落库字段这样填

- `story_mode`：**恒 `anthology`**——每一条祝福各自完整，不承接、不积累剧情记忆。
- `finale_style`：**恒 `closed`**——祝福一定落在那一句祝福语上，收得干干净净。
- `is_finale`：**恒 `false`**。

⚠️ 这三项**不问用户**，直接填，复述里不出现。

## 一个项目 = 一个场合，一集 = 一条祝福

通常一条祝福就是一集。同一个场合给多个人各做一条（给每位员工的生日祝福、给每位客户的新春问候）
= 同一个项目下的多集：场合、风格、送祝福的人沿用，每一集换被祝福的人和那一两件具体的事。

## 进入各环节时带上品类名

剧本 / 素材 / 分镜每个环节**各自有技能清单**，给了品类名就能自己定位到本目录、
照上面那张表读自己那一份。所以交给各环节的任务描述里只写品类，例如：

> 本项目品类 greeting-video，动笔前先按技能清单读它的 SKILL.md 与编剧那一份细则。

⛔ **不要替它们写文件路径**——文件名是本品类自己的事（上面那张表随时可以改），
路径写进任务描述就等于把它钉死在 prompt 里。
