# 短剧

**这是什么**：有角色、有冲突、有钩子的剧情类短视频。可以是**连续剧**（各集剧情连贯、积累剧情记忆、
有大结局），也可以是**单元剧**（每集一个独立完整的故事）。核心产物是一集一集的**故事**，
看点来自人物关系与情节反转，观众为「下一集会怎样」留下来。

**不属于本品类**：卖货口播、企业形象片、产品功能演示、活动纪实——那些没有连续的人物弧线，
访谈要问的东西完全不同，别拿这一套去套。另外三类剧情内容有自己的品类：漫画 / 动漫画风的剧情短剧、
用户点名「漫剧 / 动态漫」→ 漫剧（`anime-drama`）；猫狗等宠物当主角的拟人剧情 → 萌宠短剧（`pet-drama`）；
讲真实历史人物与事件 → 历史故事（`history-story`）。

## 各环节细则去哪看

**这张表是唯一的指引** —— 文件名由本品类自己定，读之前照这里对，不要凭约定猜。
需要哪个环节就读哪一份（都在本目录下）：

| 环节 | 文件 | 谁在什么时候读 | 里面有什么 |
| --- | --- | --- | --- |
| 访谈与落库参数 | `interview.md` | 访谈环节：建项目 / 建下一集，开口问之前 | 剧集模式 / 结局风格 / 大结局这三个短剧特有字段 |
| 编剧 | `script.md` | 剧本师：动笔之前 | 情绪弹簧、按时长选的节奏档、素材清单列什么、跨集承接与收尾 |
| 分镜 | `storyboard.md` | 分镜师：动笔之前 | 短剧的镜头节奏口径 |
| 素材 | `asset.md` | 素材师：动手之前 | 每类素材怎么写 |

⚠️ **通用的东西不在这里**：台词怎么写、人物怎么立、表演怎么写、字段清单与落库流程、
合规红线——那些对所有品类都一样，已在各角色的通用细则里。这几份只有**短剧特有的**部分。

## 落库字段这样填

`create_project` / `create_episode` 的入参是固定 schema，本品类的填法：

- `story_mode`：连续剧 `serial` / 单元剧 `anthology` —— **必问**（判据见 `interview.md`）
- `finale_style`：`closed` 完整收束 / `open` 开放式 —— **每个项目都问**，措辞随剧集模式变
- `is_finale`：**仅连续剧问**；单元剧恒 `false`
  （单元剧没有大结局这回事，标了会把项目锁死、再也建不了下一集）

## 进入各环节时带上品类名

剧本 / 素材 / 分镜每个环节**各自有技能清单**，给了品类名就能自己定位到本目录、
照上面那张表读自己那一份。所以交给各环节的任务描述里只写品类，例如：

> 本项目品类 short-drama，动笔前先按技能清单读它的 SKILL.md 与编剧那一份细则。

⛔ **不要替它们写文件路径**——文件名是本品类自己的事（上面那张表随时可以改），
路径写进任务描述就等于把它钉死在 prompt 里。
