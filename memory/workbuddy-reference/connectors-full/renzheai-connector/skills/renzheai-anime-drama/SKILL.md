# 漫剧

**这是什么**：漫画 / 动漫画风的剧情短视频——常说的 AI 漫剧、动态漫。题材多是网文小说那一路：
爽文、逆袭、穿越、重生、修仙、系统流、霸总、甜宠。竖屏、多集连载、节奏快、钩子密。
和真人短剧最大的不同在讲法上：**旁白（第一人称或第三人称讲述）比重明显更高，角色内心独白很常见**，
很多信息是「讲」出来的，画面负责把冲突、表情和爽点演足。

**画风**：本品类的画面就是漫画 / 动漫风，但**具体哪一种**（国漫、日漫、厚涂、Q 版……）由用户选，
本品类不规定、也不排除任何一种。

**不属于本品类**：
- 要真人实拍质感的剧情短剧、微短剧 → 短剧；
- 给孩子看的动画故事、儿歌、绘本 → 儿童视频；
- 动漫周边、手办、游戏的推广 → 广告片 / 电商带货。

## 各环节细则去哪看

**这张表是唯一的指引** —— 文件名由本品类自己定，读之前照这里对，不要凭约定猜。
需要哪个环节就读哪一份（都在本目录下）：

| 环节 | 文件 | 谁在什么时候读 | 里面有什么 |
| --- | --- | --- | --- |
| 访谈与落库参数 | `interview.md` | 访谈环节：建项目 / 建下一集，开口问之前 | 题材与原文、讲述视角、结局风格与大结局、默认时长 |
| 编剧 | `script.md` | 剧本师：动笔之前 | 小说改编、旁白与内心独白、爽点与钩子、系统面板这类「画面上的字」、素材清单列什么、跨集承接 |
| 分镜 | `storyboard.md` | 分镜师：动笔之前 | 漫剧的镜头节奏、旁白段落怎么配画面、爽点亮相、竖屏构图 |
| 素材 | `asset.md` | 素材师：动手之前 | 角色辨识度与跨集一致、形态变体、音色 |

⚠️ **通用的东西不在这里**：台词怎么写、人物怎么立、表演怎么写、字段清单与落库流程、
合规红线——那些对所有品类都一样，已在各角色的通用细则里。这几份只有**漫剧特有的**部分。

## 落库字段这样填

- `story_mode`：**缺省 `serial`**——漫剧就是一集接一集往下追的连载。用户明说「每集一个独立故事 / 单元剧」才用 `anthology`。
- `finale_style`：`closed` 完整收束 / `open` 开放式 —— **每个项目都问**，措辞随剧集模式变（判据见 `interview.md`）
- `is_finale`：**仅连续剧问**；单元剧恒 `false`
  （单元剧没有大结局这回事，标了会把项目锁死、再也建不了下一集）

⚠️ `story_mode` 用户没提就直接填 `serial`，不问；复述里念一句「各集剧情连着走」。

## 进入各环节时带上品类名

剧本 / 素材 / 分镜每个环节**各自有技能清单**，给了品类名就能自己定位到本目录、
照上面那张表读自己那一份。所以交给各环节的任务描述里只写品类，例如：

> 本项目品类 anime-drama，动笔前先按技能清单读它的 SKILL.md 与编剧那一份细则。

⛔ **不要替它们写文件路径**——文件名是本品类自己的事（上面那张表随时可以改），
路径写进任务描述就等于把它钉死在 prompt 里。
