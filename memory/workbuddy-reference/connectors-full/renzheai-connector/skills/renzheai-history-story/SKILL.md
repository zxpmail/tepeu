# 历史故事

**这是什么**：讲**真实历史人物与历史事件**的解说 / 再现短视频——一个人物的一生或一个转折点、一场战役、
一个朝代的兴衰、一个典故的来历、一件文物背后的故事，中国史、世界史都算。
常见形态是**旁白讲述为主线 + 场景再现**：人物、服饰、建筑、器物按时代还原，可以穿插人物的少量台词。
核心产物是**一集讲清一段史事**（一个人的一生也可以是一集）、看完让人记住一个人或一件事的片子。

**讲法可以穿越**：现代人穿越回宋朝跟着苏轼过一天、讲述人穿越到现场带观众看——只要讲的事是真实的历史，就是本品类。

**画面风格不由本品类规定**：写实古装、水墨、动画、厚涂插画都可以，用户选什么就是什么。
本品类管的是「讲历史」这件事本身——史实与演绎分开、叙事节奏、时代考据。

**不属于本品类**：
- 剧情主体是编的古装故事（宫斗、仙侠、穿越爽文、架空王朝），只是借了个朝代背景 → 短剧（`short-drama`）/ 漫剧（`anime-drama`）；
- 给小孩讲的历史小故事、成语寓言 → 儿童视频（`kids-video`）；
- 讲科学原理的「为什么」→ 知识科普（`knowledge-explainer`）。

边界判据：**片子里的人和事是真实发生过的、观众看完会把它当成历史记住吗**？是 → 本品类，讲法用没用穿越都一样。

## 各环节细则去哪看

**这张表是唯一的指引** —— 文件名由本品类自己定，读之前照这里对，不要凭约定猜。
需要哪个环节就读哪一份（都在本目录下）：

| 环节 | 文件 | 谁在什么时候读 | 里面有什么 |
| --- | --- | --- | --- |
| 访谈与落库参数 | `interview.md` | 访谈环节：建项目 / 建下一集，开口问之前 | 讲哪段历史、这一集讲到哪、资料来源、每集独立还是连着讲 |
| 编剧 | `script.md` | 剧本师：动笔之前 | 悬念开场 → 背景 → 推进 → 结局 → 余味的骨架、史实与演绎分开、旁白与台词怎么写、素材清单列什么 |
| 分镜 | `storyboard.md` | 分镜师：动笔之前 | 旁白与再现怎么交替、场面的大与小、年份地名怎么上画面 |
| 素材 | `asset.md` | 素材师：动手之前 | 人物、场景、器物按时代考据，文字素材与音色怎么写 |

⚠️ **通用的东西不在这里**：台词怎么写、人物怎么立、表演怎么写、画面文字的通用判据、字段清单与落库流程、
合规红线——那些对所有品类都一样，已在各角色的通用细则里。这几份只有**历史故事特有的**部分。

## 落库字段这样填

- `story_mode`：**缺省 `anthology`**——同一个栏目每集讲一段独立的历史（这一集讲赤壁、下一集讲淝水）。
  按时间顺序连续讲一个人物 / 一段历史、下一集接着上一集 → `serial`。判据见 `interview.md`。
- `finale_style`：`anthology` **恒 `closed`**——每集讲到一个结局、落在一句评点上；`serial` 按通用规则问。
- `is_finale`：`anthology` **恒 `false`**；`serial` 按通用规则问。

⚠️ `anthology` 时 `finale_style` / `is_finale` 不问、复述里不出现；`serial` 时照通用规则问、照通用复述模板念。

## 进入各环节时带上品类名

剧本 / 素材 / 分镜每个环节**各自有技能清单**，给了品类名就能自己定位到本目录、
照上面那张表读自己那一份。所以交给各环节的任务描述里只写品类，例如：

> 本项目品类 history-story，动笔前先按技能清单读它的 SKILL.md 与编剧那一份细则。

⛔ **不要替它们写文件路径**——文件名是本品类自己的事（上面那张表随时可以改），
路径写进任务描述就等于把它钉死在 prompt 里。
