# 知识科普

**这是什么**：**讲清一个知识点**的科普 / 解说短视频——科学原理（天为什么是蓝的）、生活常识（剩饭能不能放冰箱）、
冷知识、健康常识、财经概念（通货膨胀到底是什么），以及各种「为什么」。观众是大众成年人或青少年，
核心是**看完真的懂了一件事**，还能把它讲给别人听。

常见形态是**旁白讲解为主线 + 画面演示**：可以有一个固定的出镜讲解人，也可以纯旁白；
画面写实、动画、图解都可以，风格照通用规则让用户选，本品类不规定。
本品类管的是「讲懂」这件事本身——结构、类比、事实准确。

**不属于本品类**：
- 给 0~9 岁孩子看的简单科普 → 儿童视频（`kids-video`）；
- 有明确学员、学习目标、分步骤操作的课程 / 内训 / 教程 → 课程培训（`course-training`）；
- 讲历史人物与历史事件 → 历史故事（`history-story`）；
- 讲某个产品的功能、为了卖它 → 电商带货（`ecommerce-promo`）/ 广告片（`commercial-ad`）。

边界判据：**这条片子的目的是让观众懂一个道理，而不是学会一套操作、记住一段史事或买下一件东西吗**？是 → 本品类。

## 各环节细则去哪看

**这张表是唯一的指引** —— 文件名由本品类自己定，读之前照这里对，不要凭约定猜。
需要哪个环节就读哪一份（都在本目录下）：

| 环节 | 文件 | 谁在什么时候读 | 里面有什么 |
| --- | --- | --- | --- |
| 访谈与落库参数 | `interview.md` | 访谈环节：建项目 / 建下一集，开口问之前 | 讲哪个知识点、给谁看、资料来源、讲解人、单集还是系列 |
| 编剧 | `script.md` | 剧本师：动笔之前 | 钩子 → 类比 → 拆解 → 结论的骨架、事实纪律、解说词怎么写、素材清单列什么 |
| 分镜 | `storyboard.md` | 分镜师：动笔之前 | 画面跟着讲解走、演示怎么拍、关键概念怎么上画面 |
| 素材 | `asset.md` | 素材师：动手之前 | 讲解人、演示场景与道具、文字素材、音色怎么写 |

⚠️ **通用的东西不在这里**：台词怎么写、人物怎么立、画面文字的通用判据、字段清单与落库流程、
合规红线——那些对所有品类都一样，已在各角色的通用细则里。这几份只有**知识科普特有的**部分。

## 落库字段这样填

- `story_mode`：**缺省 `anthology`**——每集讲一个独立的知识点；系列 = 同一个讲解人 / 同一个栏目，每集一个新知识点。
  只有用户明确要「连着讲、下一集接着上一集」才用 `serial`。
- `finale_style`：**恒 `closed`**——每集都要落在一个明确的结论上，不留悬而未决的问题。
- `is_finale`：`anthology` **恒 `false`**；`serial` 按通用规则问。

⚠️ `story_mode` 用户没提就直接填 `anthology`，不问；`finale_style` 不问；这几项复述里不出现。

## 进入各环节时带上品类名

剧本 / 素材 / 分镜每个环节**各自有技能清单**，给了品类名就能自己定位到本目录、
照上面那张表读自己那一份。所以交给各环节的任务描述里只写品类，例如：

> 本项目品类 knowledge-explainer，动笔前先按技能清单读它的 SKILL.md 与编剧那一份细则。

⛔ **不要替它们写文件路径**——文件名是本品类自己的事（上面那张表随时可以改），
路径写进任务描述就等于把它钉死在 prompt 里。
