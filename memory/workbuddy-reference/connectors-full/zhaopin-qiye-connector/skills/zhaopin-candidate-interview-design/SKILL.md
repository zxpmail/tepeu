# 智联招聘｜候选人访谈设计

## 目标与边界

本 Skill 面向猎头顾问或承担猎头初筛、深度访谈的招聘人员。它根据用户明确提供或授权的职位需求、候选人材料和已知疑点，生成一套结构化访谈提纲：每个问题都对应需要了解的经历、能力、动机、约束或核验目标，并配套追问路径、有效信息提示与记录要点。

它的场景是**猎头初访 / 深聊**，用于理解候选人经历、项目贡献、求职动机、薪酬与到岗约束及需核验事实；不同于既有“面试准备”面向正式面试双方的准备材料，也不同于“面试记录结构化”对已经发生的正式面试进行整理。本 Skill 不联系候选人、不读取或发送平台消息、不访问智联简历库，也不代替用户进行真实访谈、录用/淘汰或真实性判断。

## 触发与最小输入

适用于“设计猎头初访问题”“根据简历设计深聊提纲”“为候选人筛选准备追问”等请求。最小输入为：

1. 岗位目标、职责、必备与优选条件，或经确认的人才画像；
2. 经授权的候选人简历/摘要（可选；未提供时生成通用提纲并明确局限）；
3. 已知疑点或用户特别想验证的事项（可选）；
4. 访谈目的、预计时长、阶段（初筛 / 深聊）和用户角色（如已提供）。

不得使用年龄、性别、婚育、民族、地域、外貌、口音、健康状况或其他与岗位无关的个人特征设计问题、判断动机或给出建议。默认不要求联系方式、身份证件、详细住址、账号凭据、无关家庭信息；候选人材料的授权不清时，停止处理个人内容并提供空白提纲。

## 工作流

1. **明确访谈任务**：确认是初筛还是深聊、目标岗位与预计时长；未提供时说明默认按“信息收集型初筛”组织，但不假装已知用户的招聘标准。
2. **提取可验证维度**：将职位需求拆为职责/成果、行业或专业能力、协作/管理范围、动机与约束、风险或未知项。只使用用户提供的岗位事实。
3. **生成问题路径**：对每个维度设计主问题、追问、期望获得的事实信息、应避免的无关个人问题和记录提示。优先要求候选人说明具体情境、本人行动、结果与贡献边界。
4. **候选人材料定制**：若提供简历，仅把材料中已出现的经历转换为验证性问题；未出现的内容只能问“是否有相关经历”，不能预设其存在。
5. **安排优先级**：按访谈时长区分必问、可选和时间不足时可跳过项；将需核验问题与一般了解问题区分。
6. **交付提纲**：按 `templates/candidate-interview-guide.md` 输出，给出适用时长、提问目的、问题、追问、记录字段与待验证项。

## 输出契约

输出采用三层表达：

- **事实**：仅描述用户提供的岗位要求、候选人材料中已出现的陈述或已知疑点，使用“材料显示”“候选人简历提到”等标识。
- **顾问判断**：说明为什么某项值得优先验证、问题顺序如何安排以及可能的推进风险；不得写成候选人已具有或不具有某项能力。
- **待验证项**：将材料缺失、时间线问题、成果归属不清和动机/约束未知列为访谈核验问题，不自行补全。

默认交付内容：访谈目标和时间分配、能力/事实—问题矩阵、候选人专属验证点、动机与约束问题、风险核验问题、访谈记录字段和结束问题。访谈提纲不是候选人评估结果，访谈结束后的材料可由用户在授权范围内交给“访谈记录结构化”整理，但两包不强制绑定。

## 安全、异常与升级

- 简历、职位或疑点材料缺失时，交付最小通用提纲并清楚标出不能定制的部分；不得以招聘惯例补造岗位条件。
- 遇到材料冲突，设计中性核验问题并标出冲突来源，不能选择任一版本为事实。
- 用户要求问题涉及与工作无关的个人敏感信息时，说明不建议纳入，并改为与岗位直接相关的能力、时间安排或工作条件问题。
- 用户要求发送访谈邀约、获取平台对话、更新候选人阶段、查询人才库或代表其做决定时，说明这些属于后续经授权系统能力，不模拟执行。
- 用户要为正式面试官或候选人生成正式面试准备材料时，转交既有“面试准备”能力；本包仍只服务猎头初访/深聊。
