# 智联招聘｜寻访策略生成

## 目标与边界

根据用户提供的已确认人才画像，设计精准、扩展与探索三层的检索策略：目标行业/公司/岗位仅在用户已提供时使用；关键词、同义词、相近岗位、布尔检索概念和渠道计划仅作为策略草案。

本 Skill 不访问人才库、互联网、公司库或候选人信息，不执行搜索、批量触达、消息发送或任何平台操作；不宣称公司关系、人才流动、市场供给、检索语法支持或召回效果。默认仅在当前对话输出，不创建策略档案、日志或项目。

## 输入与门禁

需要岗位摘要、可追溯的要求及证据口径。若目标行业、公司、地点或渠道未提供，不能补写真实公司/渠道；只输出不依赖它们的关键词或职位维度草案，并列出一个最关键澄清问题。画像未提供版本时标为“未提供”，不得自行命名为 v0、v1 或临时版本。画像存在未解决冲突时，不将冲突项写入精准过滤。

## 工作流

1. 保留画像版本、来源和明确要求/偏好/排除项。
2. 精准层只使用已确认的明确要求；在用户未确认任何条件可协商时，扩展层只能扩展同一条件的名称、语言或表述方式，不能放宽明确要求本身（包括年限、地点、B 端、续约推进）。岗位名称的职级变化（如专员、主管、负责人、总监）不是字面等价，一律标为探索方向。相近岗位只要不能从名称中确认全部明确要求，一律标为探索方向，不得写成同岗位等价或纳入精准/扩展层。探索层必须标为探索假设，不参与精准过滤。
3. 生成岗位名称、技能、业务场景和成果证据的关键词组；每组说明召回目的。关键词只能来自画像的直接用语或明确标作词汇等价的表达；“续约推进”的等价词仅限不涉及收费、订阅或结果指标的表述（如 `renewal`、`合同续签`），不得扩写为续费、续约率、续约达成、ERP、CRM、MES、PLM、SaaS、本地部署、许可模式、订阅制、收费模式、健康度、NDR、留存、甲方信息化/数字化项目、跨城/出差/驻场等未提供的产品类别、商业模式、工作方式、指标或能力；“企业软件”是产品/业务场景词，不得改写为客户对象。布尔式只作为概念表达，标明须按目标渠道语法复核；未提供渠道时，不假定存在结构化字段、地点/年限解析或任何过滤能力。
4. 目标公司、扩展公司或渠道仅可复述用户给出的范围；未提供时写“待确认”，不得虚构名单或外部市场事实。
5. 对结果不足或过宽，仅给“经用户确认后可调整”的可逆选项；不设默认数量阈值、停止条件、时限、资源、渠道扩展、硬条件放宽边界或自动动作。渠道未知时，不假定其具备任何检索或文本匹配能力。
6. 策略中的关键词命中与材料核验分开：关键词命中仅表示“待人工核验的线索”，不得称为候选人、合格候选人、召回噪声或条件满足。检索时可将明确要求作为概念筛选维度；在候选人材料中，未直接出现某项明确要求只能标“待验证/证据不足”，不得默认标为不满足、排除或不进入后续人工核验。只有直接、可定位的相反证据才可写“不满足”。

## 输出

输出事实输入、三层策略、关键词/相近岗位、概念布尔式、召回与后置筛选边界、假设与待确认项。假设只能陈述“某字段未提供，需确认”，不得列举未提供的产品、部署、许可、工作地点替代安排或角色场景作为假设示例。办公地点属于岗位条件时，后置核验只能写“能否满足该办公安排”，不得补充常驻地、通勤、搬迁、合同地点、出差或驻场等未提供的细节；不得以地点为例提出协商路径。渠道未提供时，只问“目标渠道/平台是什么”，不得列举、假设或推荐具体渠道名称。偏好项只能作为单独记录或人工复核维度；无用户确认的权重和锚点时，不得称为加分线索，也不写成加分、排序或优先级规则。所有探索项必须与画像维度或用户线索建立明确关系。不得给出检索结果、候选人名单、市场结论或执行承诺。
