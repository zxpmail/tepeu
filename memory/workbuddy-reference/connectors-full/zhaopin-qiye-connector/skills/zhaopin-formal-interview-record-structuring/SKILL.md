# 智联招聘｜面试记录结构化

## 目标与边界

本 Skill 面向招聘顾问、面试协作人员和招聘团队，整理用户明确提供或授权的**正式面试**转写、面试官速记、面试记录和独立反馈。它把问题、候选人回答、可定位证据、面试官评价、意见分歧和待验证项分开记录，形成后续人工复核或既有“面试反馈分析”可使用的标准输入。

本 Skill 不对证据质量进行裁决，不分析面试官偏差，不处理猎头初访或候选人私下沟通，不作录用/淘汰、薪酬、背景调查或真实性决定。它不会读取智联系统、候选人库、平台记录、邮件或聊天内容，也不会发送反馈、安排面试、更新候选人状态或导出数据。

## 触发与最小输入

适用于“整理正式面试记录”“将面试转写变成纪要”“汇总多位面试官反馈”“按岗位能力维度整理回答”等请求。输入应包括：经授权的正式面试材料、候选人代称/匿名标识、岗位或本轮面试目标（可选）、材料来源和面试轮次（如已提供），以及是否需要合并多份反馈。

处理前只请求当前任务所需信息，默认不复述联系方式、身份证件、详细住址、账号凭据、无关家庭信息或其他非必要敏感个人信息。授权范围不清、材料来源不明、文件无法可靠读取，或材料实际为猎头初访/私下沟通时，停止处理相关个人内容，说明需要的最小材料或适用 Skill。

## 工作流

1. **确认材料类型与范围**：说明材料属于正式面试转写、面试官笔记还是反馈；无法确认时列为待验证，不假定其效力。
2. **提取问题、回答与事实**：按“问题/议题—候选人回答或记录事实—可定位的经历/例子—来源”整理。口误、残句和归属不清内容不可自行改写成完整事实。
3. **保留评价层**：将面试官评价、印象和建议与候选人陈述分开；没有来源的总结不得伪装为面试官共识。
4. **记录分歧与缺口**：并列展示不同面试官、轮次或材料之间的差异，列出需要进一步确认的问题；不选择“更合理”的版本。
5. **输出标准记录**：按 `templates/formal-interview-record.md` 交付事实、评价、分歧和待验证项。只有当用户明确需要分析证据质量或意见冲突时，才将该记录作为可选输入交给既有“面试反馈分析”。

## 输出契约

默认交付包括：面试元信息与材料范围、问题—回答—证据记录、面试官评价、意见分歧、待验证项和建议补充的问题。

事实层使用“面试记录提到”“候选人陈述”“面试官笔记写明”等来源标识；顾问判断只限于记录整理优先级或补充问题建议，并说明依据与不确定性；缺失与冲突内容必须为待验证项。不得用多位面试官的数量代替事实，不输出候选人排名、录用建议、证据质量分数、合规结论或未授权个人信息。

## 异常与衔接

- 多份材料有冲突时，逐项注明来源、轮次和当前状态，不能把它们合并为唯一事实。
- 缺少岗位目标时，仍可按材料主题做中性整理；不可据此补造能力标准或评分锚点。
- 若用户需要判断反馈是否有足够证据、不同面试官为何冲突或应否进入下一轮，应使用既有面试反馈分析；本包只提供结构化材料。
- 用户要求访问平台记录、发送反馈、更新流程、联系候选人或获取账户数据时，说明这些需求属于后续经授权的系统能力，不模拟执行。
