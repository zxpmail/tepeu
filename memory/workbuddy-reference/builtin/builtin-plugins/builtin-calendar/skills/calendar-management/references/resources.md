# 日程资料与会议室

加附件走 `calendar_create` / `calendar_update` 的 `links[]`（只 `ATTACHMENT`）。`target_id` 是资料库 nodeId，不是 URL、不是腾讯文档 file_id。从资料库工具或用户给的路径取得。不要把 nodeId 写进 description 或 location。

CHANNEL 日程未传 `target_project_id` 时服务端用日历 `scope_id`（频道 ID）补齐；PERSONAL 不补。清空传 `[]`，不要传 null。最多 10 条（MCP 限制）。改附件只对单次 Event；系列实例（`CALENDAR_OCCURRENCE`）不能改附件。

每项可选 `target_role`：`reader`（可查看，不传默认）或 `editor`（可编辑）。只有这两档，别的值会被拒。档位是这条日程期望的授权，异步下发：日程已保存、附件已关联，不代表大家已经能打开或编辑。操作者对该节点没有写级权限时，授权会静默失败（日程和附件行仍在，同事打不开）。分别报告：日程已保存 / 附件已关联 / 权限仍在同步。不要说「已经通知参与人」，也不要在用户没指定时说成可编辑。不要再调 set-permission 或任何资料库授权工具。

移除链接会撤销**本日程**的授权，不影响该文件在其他业务上的权限。公开日历订阅者与盲加入者不在授权成员口里，他们能看到日程但打不开附件。

用户只给模糊资料名时，在授权范围内检索，多个匹配按 SKILL「不确定时提问」选（优先 `send_card`），不随意点同名资料。更新后要看附件用 `calendar_show`，`calendar_update` 回参没有 links。

## 会议室查询与预订

仅非全天、非循环日程支持预订会议室。用户要求会议室时，用已选日程完整起止时间查询空闲会议室；时间未定先确定时间，或结合排期候选查询。地点、容量和设备要求只用用户提供或授权上下文中的依据，缺少会影响选择的信息时合并问答；不要机械补问所有可选筛选项。

候选需来自真实工具结果。用户明确指定且可用时可按授权预订；有多个可选项且用户未委托自动选择时，按 SKILL「不确定时提问」选择（优先 `send_card`）。不可用时给替代会议室或时间，不静默替换。

提交前由资源服务再次校验空闲；查询到空闲不等于锁定成功。预订工具返回成功后才能说已订会议室，location 文本不是预订回执。资料授权、会议室等附属步骤与日程写入的执行顺序按工具实际契约，不假定具有跨服务事务。

改期时检查并调整预订；更换会议室或取消日程时释放原预订，由现有联动完成则不再重复调用。分别报告日程和资源结果，不能因日程取消就假定释放已成功。
