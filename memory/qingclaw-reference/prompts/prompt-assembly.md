# QingClaw 提示词组装系统（客户端源码还原）

来源：`.renderer/qingclaw-foxbHnSS.js`（minified，函数名为混淆后随机名，本文用源码中的名字 xt/St/Ct/wt/Tt 指代）。

## 总装函数

```js
// 最终提示词 = 场景正文 + "\n\n" + 能力后缀 [+ 示例数据条款 + 门户条款]
function Tt(capability, scenario, section, title) {
  const suffix = xt[capability];
  const expanded = capability === 'system-builder' && section
    ? `${suffix}${wt(section)}\n${Ct(sectionKey, title)}`
    : suffix;
  return `${scenario.prompt.trim()}\n\n${expanded}`;
}
```

要点：**编号清单跨三个函数拼接**——xt 给 1–4，wt 追加第 5 条（仅 completeSystem），Ct 追加第 6 条（门户设计）。场景正文自身不带编号，永远是"业务描述在前、通用要求在后"的两段式。

## xt：四能力通用后缀（每条场景都会拼上）

**todo（待办处理）**
1. 先说明筛选待办的口径、时间范围和排序依据。
2. 按紧急程度、业务影响、等待时长和责任人维度归类。
3. 对每个重点事项给出当前状态、阻塞原因、建议动作、建议完成时间和需要协同的人。
4. 最后输出一份可直接执行的优先级清单，并标记需要我立即处理的事项。

**data-entry（数据录入）**
1. 先识别原始信息中的实体、记录边界、字段含义和可能的关联关系。
2. 为每个字段建议字段类型、是否必填、示例值、校验规则和可能的枚举选项。
3. 标记重复、缺失、格式异常和口径不一致的信息。
4. 输出清洗后的表格结构和可导入轻流的数据示例。

**data-analysis（数据分析）**
1. 先说明分析目标、数据口径、时间范围和关键指标定义。
2. 按业务对象、负责人、阶段/状态、时间和金额/数量等维度做分组比较。
3. 找出异常值、趋势变化、效率瓶颈、风险项和可能原因，并说明判断依据。
4. 输出结论摘要、关键数据表、优先处理清单、改进建议和后续需要补充的数据。

**system-builder（系统搭建）**
1. 应用清单与数据关系。
2. 每个应用的表单结构：字段、字段类型、必填项、枚举值和关联字段。
3. 关键流程节点、处理规则和提醒规则。
4. 具体视图类型：列表、看板、日历、统计报表、数据仪表盘等，并说明用途。

## wt：示例数据条款（仅 completeSystem 模板）

> 5. 示例数据要求：每个应用一般生成 5 条左右示例数据，数据要能覆盖核心状态、角色、流程节点和报表统计口径。

注意与单应用模板的差异：单应用正文自带"生成 12 条示例数据"（单表 12 条），系统级走 wt（每应用 5 条，强调覆盖状态/角色/节点/口径）。示例数据的量与"覆盖什么"都显式声明。

## Ct：门户条款 + St：七域报表词表

```js
St = {
  'oa-office':   '公告阅读统计、审批效率、费用趋势、资产使用、用品库存、会议室使用率等行政运营报表',
  sales:         '线索转化漏斗、商机阶段看板、合同回款、客户跟进、销售预测、续约风险等销售经营报表',
  procurement:   '采购需求进度、订单交付、供应商表现、价格波动、库存预警、付款对账等采购供应报表',
  production:    '生产计划达成、工单进度、工序效率、质量异常、物料齐套、设备停机等生产现场报表',
  project:       '项目进度、里程碑达成、任务延期、问题风险、变更影响、资源工时等项目管理报表',
  equipment:     '设备状态、维保到期、维修工单、故障频次、备件库存、利用率和安全隐患等设备运维报表',
  finance:       '预算执行、费用归集、应收应付、回款逾期、付款计划、现金流预测、项目成本等财务报表',
  (default):     '进度、效率、风险、成本、质量和趋势等关键运营报表',
}
Ct = (sectionKey, title) =>
  `6. 针对「${title}」场景设计专门门户：说明门户首页布局、角色入口、核心指标卡片、快捷操作，并明确需要展示的报表类型，例如：${St[sectionKey] ?? 默认}。`
```

这是**域词表注入**：同一句门户指令，按场景域喂不同的报表类型示例，把"报表"从抽象词落到具体指标。

## 自由搭建兜底提示词

> 帮我搭建一个轻流业务系统。请设计业务场景、应用、字段、视图、流程、报表和门户，并执行搭建。

## 可学习的结构决策

1. **两段式**：场景特定正文 + 能力通用后缀分离。改通用要求只动 xt，不动 108 条场景。
2. **编号续接**：后缀的 1–4 / 5 / 6 由不同函数产出，拼出来仍是一条完整清单——模块化但不散装。
3. **词表注入**：St 把"设计报表"这类抽象要求实例化为域内指标清单，防 LLM 泛泛而谈。
4. **覆盖性示例数据**：不只要求"生成 N 条"，还声明数据要覆盖核心状态、角色、流程节点、统计口径——为后续分析/看板演示备料。
5. **输出物清单化**：每条场景提示词都以"请输出 X、Y、Z"收口，输出物可验收。
